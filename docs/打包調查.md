# 打包成 Windows .exe：調查、決定與步驟

第一階段（2026-10-14）的調查結果與使用者的決定。第二階段每一步開新視窗時先讀這份。
來源都是 2026-10-14 查的官方文件或 PyPI，實測數字都在這台電腦（RTX 4070 Laptop、Windows 11）量的。

## 使用者的決定（2026-10-14）

1. **程式碼公開，用 GPLv3 授權**（av 附的 x264/x265 是 GPL、載入在本程式程序裡，公開最單純）。
2. **資料位置**：設定類（config.json、介面設定、網址紀錄、版面配置、overlay 位置、詞庫、logs、翻譯錯誤紀錄）放 `%LOCALAPPDATA%\直播摘要`；
   輸出（直播稿、摘要、聊天室、逐句翻譯、音訊）放「文件\直播摘要」（用 Windows Known Folder API 取得，OneDrive 重新導向也對）。~~沒打包時維持專案資料夾~~ → **2026-10-14 第2步改為：開發（直接跑 app.py）和打包版用同一套位置**，第一次啟動時從專案資料夾複製程式資料過去（舊輸出檔不搬）。
3. **第一版用壓縮檔**（免安裝資料夾），不做安裝程式。
4. **ffmpeg 改用 BtbN 的 LGPL shared 版**，固定某一版並備份對應原始碼。
5. **不附 cuDNN**（省 1.1 GB），第三階段驗證其他顯示卡。
6. **開發環境改用 Python 3.13**。

## 第二階段步驟（使用者調整後的順序）

1. 鎖版本（完整鎖定檔、av 釘 17.1.0）＋開發環境換 3.13＋LICENSE（GPLv3）。
2. ✅（2026-10-14 完成）集中路徑：新增路徑模組 app_paths.py；config.py、ui_state.py、glossary.py、panel.py、startup_timeline.py、subtitle.py（翻譯錯誤紀錄）、
   app.py（啟動時的 os.chdir）、settings_page.py（「存在專案資料夾」的文字＋「打開資料夾」按鈕）改用它；加測試。
3. 另開程序與函式庫位置：live_capture.py（組 streamlink 指令的函式、CREATE_NO_WINDOW、先找附帶的 ffmpeg）、
   新增 helper（命令列版 exe）進入點、transcribe.py（打包後找 cuBLAS 的位置）、first_run.py（訊息文字）。
4. 打包設定：`直播摘要.spec`、`scripts/build_exe.py`，第一次打包，修打包後才出現的問題（漏收的模組、資料檔）。
5. 介面補強：系統匣說明頁＋打開工作列設定的按鈕、無視窗模式的錯誤寫進 logs、偵測在壓縮檔裡執行、圖示（.ico）與版本號。
6. 授權與文件：ffmpeg、Qt、NVIDIA、第三方套件的授權文件，給一般使用者的 README，做壓縮檔。

之後第三階段：Windows 沙箱等乾淨環境測試（另外要測中文帳號名稱、其他型號顯示卡）。

## 1. Python 版本：3.13

- 3.10 已在 2026-10-01 停止支援；3.13 支援到 2029-10（devguide.python.org/versions）。
- 3.12 官方最後附安裝程式的是 3.12.10（2025-04），之後只出原始碼；3.13.16（2026-09-30）有官方 64 位元安裝程式（python.org/downloads/windows）。
- yt-dlp 2026.07.04 發布說明：建議版本提高到 3.11，3.10 的支援很快會拿掉。
- PyPI 逐一查過：requirements 裡所有套件（含相依）的釘選版本都有 cp313 或 abi3 的 Windows 安裝檔。av、onnxruntime 的最新版已不支援 3.10。
- 3.14 不選：numpy 2.2.6 沒有 cp314 安裝檔。
- **相依套件一定要鎖版本**：沒鎖時 3.13 環境裝到 av 19.0.1，faster-whisper 1.2.1 解碼音訊檔失敗
  （`TypeError: open() got an unexpected keyword argument 'metadata_errors'`）。直播轉錄傳 numpy 陣列不受影響，
  transcribe.py、scripts/vod_to_transcript.py 傳檔案路徑會壞。pytest 用假模型，抓不到這種問題 → 打包前一定要用真模型實測。

## 2. 打包工具：PyInstaller、資料夾形式（onedir）

- PyInstaller 6.22.3（2026-09-12）、pyinstaller-hooks-contrib 2026.8（2026-09-30）。
- 不用單一檔案：每次啟動要把約 1 GB 解壓到暫存資料夾，啟動慢；當掉時 `_MEI…` 不會刪（pyinstaller.org operating-mode）；也比較容易被防毒誤判。
- 預估大小（實測各元件）：cuBLAS 771 MB、PySide6 約 100～150 MB（只收用到的）、av 69 MB、ctranslate2 60 MB、numpy 55 MB、
  onnxruntime 48 MB、ffmpeg 約 70～110 MB、其他約 60 MB → 資料夾約 1.2～1.3 GB，壓縮檔約 0.8 GB。
- 轉錄模型不附（1.6 GB），維持第一次啟動時下載（first_run.py）。
- 打包時不用 UPX（`--noupx`），用 `--windowed`、`--icon`、`--version-file`。

## 3. streamlink 另開程序

- 打包後 `sys.executable` 是 exe 本身，`-m streamlink_cli`、`yt_audio.py` 都會失效（vod_to_transcript.py 是開發工具，不打包）。
- 做法：同一個打包資料夾多做一個命令列版 helper.exe（spec 裡兩個 EXE 共用一個 COLLECT／_internal），用參數切換 streamlink 模式與 yt_audio 模式。
  live_capture.py 由一個函式組指令：沒打包維持 `sys.executable -m streamlink_cli`，打包後改 `helper.exe --streamlink …`。
- 不讓主程式 exe 自己切換：主程式是無視窗模式，用管線傳二進位 stdout 是否可靠沒驗證；命令列版 exe 一定可以。
- 不改成程式內呼叫 streamlink：要重寫 streamlink → ffmpeg 的管線，停止時也不能直接 kill，改動大。
- 無視窗程式開 ffmpeg／helper 要加 `CREATE_NO_WINDOW`，不然會閃黑色命令列視窗（first_run.py 已有，live_capture.py 還沒有）。
- streamlink 外掛要 `collect_submodules('streamlink.plugins')`。

## 4. 顯示卡函式庫（實測）

- 轉錄時列出程序實際載入的 DLL：只有 `cublas64_12.dll`、`cublasLt64_12.dll`（771 MB）；nvidia-cudnn（1.1 GB）、nvrtc（179 MB）都沒載入。
  ctranslate2 自己附一個 cudnn64_9.dll 小檔。
- 只給 cuBLAS 也正常；兩種設定的差異和同一設定跑兩次的差異一樣大（26～32 行，顯示卡運算的正常浮動）。
- **只用 `os.add_dll_directory` 會失敗**（找不到 cublas64_12.dll），一定要同時加進 PATH（transcribe.找顯示卡函式庫 現在兩個都做）。
- 打包：cuBLAS 放 `_internal/nvidia/cublas/bin`，找顯示卡函式庫() 打包後改找 `sys._MEIPASS`。
- 授權：CUDA EULA 附件 A 列 cublas.dll、cublasLt.dll 為可散布（檔名可帶版本號）；只能給本程式用、不能移除版權聲明。
- 只在 RTX 4070 Laptop、large-v3-turbo、float16 測過。cuBLAS 12.9 需要的最低驅動版本還沒查（第二階段查 CUDA 相容性文件寫進 README）。

## 5. ffmpeg 與授權

- 現在用的 Gyan 9.0.2 full_build：gyan.dev 寫明所有版本都是 GPLv3；ffmpeg.exe 228 MB、編進幾十個函式庫，散布要附全部對應原始碼。
- 改用 BtbN `ffmpeg-n9.0-latest-win64-lgpl-shared-9.0`（73.7 MiB，2026-10-13 版）：固定某一天的版本、自己備份那一版原始碼，
  放在和下載檔同一處；附 LICENSE；關於畫面與下載頁寫明有用 FFmpeg（照 ffmpeg.org/legal 清單）。
- 我們是另開程序呼叫 ffmpeg，ffmpeg 的授權不影響本程式碼。
- av（faster-whisper 必裝）17.1.0、19.0.1 都附 libx264、libx265（GPL），載入在本程式程序裡 → 決定公開用 GPLv3。
- PySide6 是 LGPLv3：資料夾形式 Qt DLL 可替換，附 LGPL 授權文字與 Qt 原始碼位置。

## 6. 檔案寫在哪裡

- 見上面決定 2。不放 exe 旁邊：更新時使用者刪舊資料夾、解壓新的，資料會跟著不見；Program Files 也寫不進去。
- ~~舊資料不自動搬~~ → 2026-10-14 改為：第一次啟動時新位置（%LOCALAPPDATA%\直播摘要）沒有任何檔案、專案資料夾有舊資料，就「複製」config.json、config.backup.json、介面設定、網址紀錄、版面配置、翻譯錯誤紀錄、詞庫、logs（舊檔不動）；打包版沒有舊位置，不搬。舊的輸出檔與 overlay_位置.json 不搬（使用者決定）。
- 實測注意：從 Claude 桌面版（MSIX 套件）裡啟動 app.py，寫進 %LOCALAPPDATA% 的檔案會被轉到 `AppData\Local\Packages\Claude_…\LocalCache\Local\直播摘要`；從檔案總管或一般終端機啟動才是真正的位置。

## 7. 其他

- keyring：PyInstaller 本身有 hook-keyring（收所有後端＋套件資訊），不用另外處理；3.13 實測後端 WinVaultKeyring。
- yt-dlp 保護機制：打包後只有 .pyc、讀不到原始碼，`yt_chat.檢查可中斷等待()` 走「只看模組結構」。
  spec 裡對 `yt_dlp.downloader.youtube_live_chat` 設 `module_collection_mode='pyz+py'`，附原始碼讓完整檢查也能跑。
  yt-dlp 自帶 PyInstaller hook（yt_dlp/__pyinstaller）。
- faster-whisper 的 `assets/silero_vad_v6.onnx` 一定要列為資料檔（不然 vad_filter 壞）；onnxruntime 有 hook。
- 轉錄模型：維持 Hugging Face 預設快取（`%USERPROFILE%\.cache\huggingface\hub`）。2026-10-14 實測（ctranslate2 4.8.2、faster-whisper 1.2.1、系統字碼頁 950）：把 small 模型放到 `Users\小明`、`Users\这个`、`Users\한국`、`Users\テスト`、`Users\Zoë` 底下，ctranslate2 直接載入、faster-whisper 整條（含 tokenizer、轉錄一段）在 cuda／cpu 都成功；含 cp950 表示不了的字也成功，表示不是靠 ANSI 字碼頁。第三階段仍要用真的中文帳號（最好再加英文語系的 Windows）跑一次下載＋轉錄確認。
- 系統匣圖示收在「^」裡：首次引導加一頁說明＋按鈕打開 `ms-settings:taskbar`（Microsoft Learn Settings URI 表，2026-09-26 版）。
- SmartScreen／防毒：沒簽章會跳「Windows 已保護您的電腦」→「其他資訊」→「仍要執行」；README 教「解壓前對壓縮檔按右鍵 → 內容 → 解除封鎖」；
  每次發版前把 exe 送 Microsoft 安全情報中心回報誤判（這部分資料多是 Microsoft Q&A、憑證廠商文章，不是正式文件）。
- 圖示與版本號：目前沒有 .ico（系統匣圖示是 capsule.py 畫的）；要做 .ico、版本號模組，寫進 exe，關於畫面顯示。
- 無視窗模式當掉看不到錯誤：加全程式錯誤攔截寫進 logs。

## 8. 發布：壓縮檔

- 沒簽章的安裝程式一樣被 SmartScreen 擋，還要處理移除程式、Program Files 寫入；壓縮檔出問題刪資料夾就好。
- 有人會在檔案總管直接打開壓縮檔執行 → 偵測執行路徑在暫存資料夾的壓縮檔裡時跳說明。
- 0.8 GB 單一檔案：要查發布平台的單檔大小上限。

## 風險

- 打包版沒有自動更新：YouTube／Twitch 改版要等新版 → 版本號要看得到，README 寫去哪下載新版。
- 沒簽章＋0.8 GB＋PyInstaller，防毒誤判機率高；公司電腦可能打不開。
- NVIDIA 驅動太舊會退回 CPU；CPU 跑 small 跟不上直播（介面已有提示）。
- 中文帳號名稱、其他顯示卡型號都還沒測。
