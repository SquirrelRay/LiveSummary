直播重點摘要（階段 1）

==============================================================================
  【下載後請先把整個壓縮檔解壓縮，再執行 LiveSummary.exe】
  不要在壓縮檔裡直接點開 LiveSummary.exe：Windows 只會取出那一個檔案，程式一定跑不起來
  （會出現英文的「Failed to load Python DLL」錯誤）。做法：在 LiveSummary-v版本號.zip 上按右鍵
  → 全部解壓縮，再到解壓縮出來的 LiveSummary 資料夾裡雙擊 LiveSummary.exe。

檔案放在哪裡（2026-10-14 起；直接跑 python app.py 和打包版都一樣，不再往程式資料夾寫東西，位置只由 app_paths.py 決定）：
  程式資料：%LOCALAPPDATA%\LiveSummary（通常是 C:\Users\你的帳號\AppData\Local\LiveSummary；2026-10-14 打包第4步以前是 …\Local\直播摘要）
    config.json、config.backup.json、介面設定.json、網址紀錄.json、版面配置.json、翻譯錯誤紀錄.txt、詞庫\、logs\
  輸出：「文件」\直播摘要（直播稿、分鐘摘要、話題摘要、聊天室、逐句翻譯；給人看的，維持中文名稱）
  除錯用音訊：%LOCALAPPDATA%\LiveSummary\音訊\（每場一個「頻道_日期_時間_音訊」資料夾，裡面是每段一個 wav）。
    不放「文件」：音訊很大，「文件」常被 OneDrive 接管、會自動上傳。程式沒有任何功能會讀這些音訊，只供人工除錯。
    只保留最近 5 場（含正在錄的這場）：每次開始新的一場（且打開存音訊）時，刪掉最舊的；只刪這個資料夾底下、名稱符合上面格式、
    裡面只有 wav 的資料夾，其他東西一律不碰。想留某一場請先把它的資料夾複製到別處。
    已經在「文件」\直播摘要 或專案資料夾裡的舊音訊資料夾不搬也不刪，要的話自己手動處理。
    「文件」用 Windows 正式的方式取得（Known Folder）：被 OneDrive 或其他磁碟接管時跟著走，例如 C:\Users\你的帳號\OneDrive\文件\直播摘要。
    設定框「存檔」區的「打開存檔資料夾」直接打開這裡。
  API 金鑰仍只存在 Windows 認證管理員，不在上面任何檔案裡。
  搬家：第一次啟動時，程式資料位置（LiveSummary）還沒有任何檔案 → 從舊位置把上面那些程式資料「複製」過去（舊檔不動、不刪），
    膠囊旁與主控台提示條說一聲從哪裡複製了什麼，也記在 logs\搬家紀錄.txt。程式資料位置已經有檔案就完全不碰（只有空資料夾不算）。
    舊位置依序找，第一個有程式資料的才搬（只從一個地方搬，不混在一起）：
      1. %LOCALAPPDATA%\直播摘要（改名前的位置；直接跑 app.py 和打包版都會找）
      2. 專案資料夾（更早以前的位置；只有直接跑 app.py 時）
    舊位置的除錯用音訊（直播摘要\音訊）不搬；舊的輸出檔（直播稿、摘要）不搬；overlay_位置.json 已經沒有程式讀，也不搬。
    舊位置的東西確認不需要後可以自己刪。想重新搬一次：關掉程式，把 %LOCALAPPDATA%\LiveSummary 整個資料夾改名或刪掉，再開程式。
  注意：從 Claude 桌面版等「市集安裝的 App」裡面啟動 python app.py 時，Windows 會把寫進 %LOCALAPPDATA% 的檔案轉到那個 App 自己的
    AppData\Local\Packages\…\LocalCache\Local\LiveSummary（套件虛擬化），從一般終端機或檔案總管啟動才會用真正的位置。
  例外（不屬於上面兩類，維持原樣）：轉錄模型在 Hugging Face 的快取（%USERPROFILE%\.cache\huggingface）；
    YouTube 聊天室的暫存在系統暫存資料夾（結束就刪）；文字稿重播模式與 transcribe.py 處理本機檔案時，結果存在來源檔旁邊；
    開發用的 測試素材\（scripts/vod_to_transcript.py）在專案資料夾。

第一次設定：
1. 安裝套件：建立開發環境 .venv（見最後的「開發環境」；套件版本見 requirements.txt 與 requirements-lock.txt）；
   ffmpeg：跑 .venv\Scripts\python.exe scripts\下載ffmpeg.py 下載隨附版（優先使用），沒下載時改找系統上裝的（winget install Gyan.FFmpeg）
2. 設定金鑰：打開程式，啟動面板會顯示「尚未設定 API 金鑰」→ 按「設定金鑰」→ 貼上金鑰 → 按「測試連線」（成功就會記住）。
   金鑰存在 Windows 的「認證管理員」（控制台 → 認證管理員 → Windows 認證，名稱含「直播摘要」），不會寫進任何檔案。
   每家服務（Claude、OpenAI、DeepSeek、其他相容服務）各存一把，切換服務時各自的金鑰都還在。
   進階：仍然可以用環境變數（setx ANTHROPIC_API_KEY "你的金鑰"，設完重開終端機）；這台電腦已儲存的金鑰優先。

第一次使用（python app.py）：
  第一次打開程式會出現「使用說明」引導，三頁，可以按左下角「跳過」：
    1. 設定模型與金鑰：選模型服務、貼上金鑰、按「測試連線」（成功出現綠色 ✓ 才算好）；「如何取得金鑰」打開官方網頁；下面是每小時費用估算。
       這一頁和設定框的「模型服務與 API 金鑰」是同一個元件；按「下一步」時，換過的服務、模型才會寫進設定。
    2. 檢查這台電腦：自動檢查 NVIDIA 顯示卡、ffmpeg、streamlink，每項顯示 ✓（沒問題）、⚠（能用但有提醒）、✕（要先處理）；
       只有 ⚠／✕ 的項目右邊有「怎麼處理？」，點了在那一項下面展開 1～2 句。
       顯示卡只做輕量偵測（問顯示卡函式庫有幾張可用的卡，不載入轉錄模型），超過 4 秒就顯示「⚠ 無法確認顯示卡：開始後會自動判斷」。
    3. 開始使用：貼上 Twitch 頻道或 YouTube 直播網址 → 按開始 → 面板出現。第一次開始會下載轉錄模型：
       有可用的 NVIDIA 顯示卡下載 large-v3-turbo（約 1.6 GB），沒有就下載 CPU 用的 small（約 486 MB）；已下載過顯示「轉錄模型已準備好」。
  看過一次（看完、跳過或關掉）就不再自動出現，記在本機的 介面設定.json（「引導看過」，不進 git）；
  沒有金鑰不會讓引導再跳出來（啟動面板的「尚未設定 API 金鑰」提示條會處理）。想再看：膠囊或系統匣選單的「使用說明」。
  想重看「第一次」的樣子：把 介面設定.json 裡的 "引導看過" 改成 false（或刪掉這一行）再開程式。
  轉錄模型下載（第一次按開始）：
    怎麼判斷下載過：看 Hugging Face 的快取（%USERPROFILE%\.cache\huggingface\hub\models--組織--名稱\snapshots\*），
      找得到 model.bin、config.json、tokenizer.json 就算已下載（只看檔案，不連網）。
    下載中啟動面板不會收起，顯示進度條、「已下載 0.8／1.6 GB」與已等時間；下載好、模型載入完才收起並出現面板。
      進度是每 0.5 秒量一次快取資料夾裡這次寫入的檔案大小，除以模型的檔案總大小（first_run.py 的 模型大小 表）；
      表裡沒有的模型（自己改 whisper_model）取不到總大小，改顯示會動的進度條＋已等時間。
    確定沒有可用的 NVIDIA 顯示卡時直接用 small，不會先下載用不到的大模型；直播中顯示卡失敗退回 CPU、要另外下載 small 時，
      啟動面板會重新打開顯示這次下載（約 486 MB），下載好自動收起。
    下載失敗用白話說明：連不上網路、硬碟空間不夠（附模型大小）、其他（請稍後再按一次開始）。
  文字稿重播（開發測試用）：主控台的來源預設只有「直播網址」；設定框最下面「開發者選項」勾「顯示文字稿重播模式」才出現「文字稿檔案」
    （勾了立即生效，記在 介面設定.json）。命令列的文字稿模式（python live_topics.py 稿.txt …）不受影響，照舊可用。
  開發用截圖：python scripts/引導截圖.py（全部假資料，存到 測試素材/引導截圖/；--scale 1.5 模擬 150% 縮放，--sizes 印出各縮放下需要的大小）。

使用：
   python summarize.py sample.txt --type game
   python summarize.py 文字稿.txt --type chat

結果會印在畫面上，並存成「原檔名_摘要.md」。

設定檔 config.json（用 live_topics.py 時；放在 %LOCALAPPDATA%\LiveSummary，見最上面「檔案放在哪裡」）：
  功能開關和常用數字都寫在 config.json，用記事本打開改就好，改完存檔，下次執行就生效。
  config.json 是本機檔案，不進 git；git 裡只有範例 config.example.json（內容 = 出廠預設）。
  沒有 config.json 時（例如剛 clone）程式照常啟動、全部用出廠預設，不會自動建立；
  想用記事本改就把 config.example.json 複製成 %LOCALAPPDATA%\LiveSummary\config.json 再改，或直接在設定框按「儲存」（會建立 config.json）。
  預設值、欄位檢查、欄位說明、語言清單、讀寫 config.json 的程式都在 config.py（新增欄位只要改那裡，加上設定框）。
  命令列參數只是「這一次」臨時覆蓋，優先順序：命令列 > config.json > 程式內建預設。
  欄位：chat（聊天室）、minute_summary（分鐘摘要）、save_audio（存音訊）、fix_with_chat（聊天室參考詞修正）、
        check_minutes、min_topic_min、max_topic_min、model、whisper_model、language、minute_sentences（1 到 3）。
  看目前實際生效的設定與來源：  python live_topics.py --show-config
  臨時覆蓋範例：  --no-chat / --chat、--no-minute / --minute、--no-save-audio / --save-audio、--fix / --no-fix
  注意：API 金鑰不要寫進 config.json。金鑰在設定框輸入（存在 Windows 認證管理員，見 api_key.py）；
  讀取順序：認證管理員 → 環境變數（預設各家的 ANTHROPIC_API_KEY／OPENAI_API_KEY／DEEPSEEK_API_KEY／OPENROUTER_API_KEY／GEMINI_API_KEY，api_key_env 改過名字就照舊用那個）。
  金鑰無效時，程式會用一句中文停下來，不會繼續空跑。

外語直播（日文等）：
  config.json 的 language 可填 "zh"（預設，中文）、"ja"（日文）、"en"（英文）、"ko"（韓文）、"auto"（自動偵測）。
  命令列臨時覆蓋：  python live_topics.py --live 網址 --lang ja     或   --lang auto
  auto：用第一段（8～20 秒，依字幕速度）有人聲的音訊判斷語言（靜音或只有音樂的段會跳過、等下一段），判斷出來就鎖定，之後都用這個語言；失敗會印警告並退回中文。
  不管直播什麼語言，摘要一律是繁體中文；專有名詞第一次出現會附原文，看不懂的詞會標「不確定」。
  簡體字轉繁體（traditional.py，用 OpenCC 的 s2tw）：Whisper 轉出的中文稿有時是簡體，模型會照抄人名、詞語，
    所以分鐘摘要、話題摘要、支線、目前話題簡述、逐句翻譯、聊天室翻譯在顯示與存檔前再轉一次繁體。
    只轉「有確定簡體字」的子句，本來就是繁體的句子一字不動（干擾、于先生、台灣不會被改）。
    不轉：詞庫裡手動、上網的顯示寫法與原文；括號裡含假名的原文；外語直播括號裡的原文（日文人名的漢字，例如 国木田）。
    直播稿本身不轉（照轉錄原樣存）。沒裝 opencc 時照原樣輸出，不會出錯。
  轉錄外語影片：  python transcribe.py 影片或網址 --lang ja
  文字稿模式跑外語稿：  python live_topics.py 日文稿.txt --lang ja
  --show-config 會顯示 language 目前的值與來源。

切換語言模型（設定框的「模型服務與 API 金鑰」）：
  1. 「模型服務」下拉選單：Claude（正式支援）、OpenRouter（一把金鑰用多家模型；想用 GPT 等其他家的模型，可以透過 OpenRouter）、
     DeepSeek、Google Gemini、Ollama（本機，不用金鑰）、其他相容服務（自己填網址）。
     OpenAI 直連暫時不列在選單：原因是呼叫方式未驗證（官方模型頁寫的是 Responses API，本工具用的是 chat completions，
     而且沒有金鑰可以實測）。程式裡的目錄、金鑰、單價都保留，model_catalog.py 的 OpenAI直連顯示在選單 改成 True 就會恢復。
     舊的設定已經是 OpenAI 的話照常能讀、能用：設定框顯示成「其他相容服務」並帶入原本的網址，金鑰與費用估算照常。選了會自動帶入服務網址、對應的金鑰欄位與「如何取得金鑰」連結；
     只有「其他相容服務」才顯示網址欄。Claude 以外都標「實驗性」：提示詞是用 Claude 調整的，其他模型的格式與品質可能不穩定。
  2. 「模型」下拉選單：每個服務列 2～4 個推薦模型（白話名稱＋一句說明，預設選「建議」的那個），滑鼠停著顯示單價與查證日期。
     最後一項「其他（自己輸入）」才出現文字欄，給進階使用者打模型代號。
  3. 進階：「載入可用模型」用列出模型（不花錢）把服務實際提供的模型放進選單的進階區塊；清單很長（例如 OpenRouter）可以輸入關鍵字篩選。
     Ollama 的推薦清單就是這台電腦已下載的模型（選了 Ollama 會自動讀；一個都沒有時會說明要先用「ollama pull 模型名稱」下載）。
  4. 按「儲存」才寫入。換服務時服務網址、模型、單價一起換，舊服務的值不殘留；切回原本記住的服務會還原原本的模型。
  上網查證只有直接連 Claude 時能用；選其他服務（包括透過 OpenRouter 用 Claude）時勾選會停用並寫原因。
  呼叫模型的程式都在 llm.py；服務、推薦模型、單價的清單在 model_catalog.py。summarize.py 單獨使用時仍固定用 Claude。
  用 Claude 以外的服務要先裝套件：pip install openai（requirements.txt 裡標為選用）。
  金鑰無效、或連不上伺服器（例如 Ollama 沒開）時，程式會用一句中文說明並停止。拿不到 token 數的服務，結束時會顯示「無法計算」。

  費用估算的單價（每百萬 token 美元，2026-10-13 查各家官方定價頁，寫在 model_catalog.py）：
    推薦模型都有官方單價；OpenRouter「載入可用模型」時清單裡附的單價會自動帶入。注意 OpenRouter 清單列的是「最便宜供應商」的價格
    （同一個模型有幾十家供應商、價格差很多，例如 DeepSeek V4.1 Flash 輸入 0.044～0.60），實際依路由到的供應商而定，可能較高；
    所以 OpenRouter 的推薦模型取多數供應商的官方價，不用最便宜的活動價。
    Gemini 3.1 Flash Lite 比 3.5 Flash Lite 便宜，但官方公告 2027-05-07 停用（接替是 3.5 Flash Lite），所以建議選 3.5。
    「其他（自己輸入）」、清單外沒附價格的模型：單價未知，啟動面板、設定框費用表、膠囊、狀態列、結束訊息一律顯示
    「單價未知，無法估算」，不會沿用之前別的模型的單價。DeepSeek 用尖峰價估算（離峰半價）；Ollama 本機不花錢（$0）。
    Claude Haiku 5.5 提示詞超過 10 萬 token 時官方是 0.50／2.50，這個階梯價沒有實作（話題摘要與判斷的提示詞遠低於 10 萬 token）。

  進階：直接改 config.json（設定框沒有要改的需求時不用碰）：
    provider     ："anthropic"（Claude）或 "openai_compatible"（其他服務）
    base_url     ：服務網址，空白 = 該家預設（各家網址見 model_catalog.py）
    model        ：模型代號
    api_key_env  ：金鑰放在哪個「環境變數名稱」（不是金鑰本身！）；留空 = 不需要金鑰。
                   一般情況不用改：金鑰在設定框輸入；出廠值 ANTHROPIC_API_KEY 代表「用各家預設的環境變數名稱」。
    price_input / price_output / price_model：自己指定單價。只有 price_model 等於目前的 model 時才採用；
                   否則用內建價目表，查不到就顯示單價未知。設定框選模型時會自動填這三欄。
    舊的 config.json（只有 provider＋base_url＋model）會自動對到服務與模型：模型不在推薦清單就顯示成「其他（自己輸入）」並帶入原本的代號；
    網址對不到已知服務就當「其他相容服務」。
    金鑰怎麼區分服務：Claude、OpenRouter、api.openai.com、api.deepseek.com、Gemini 各一把；其他網址用「主機/路徑」各一把；
                   localhost／127.0.0.1（Ollama 等本機服務）不需要金鑰。

聊天室翻譯（介面才有；config.json 的 chat_translate，預設關；舊的 config.json 沒有這兩個欄位也當作預設、不跳警告）：
  外語直播時把聊天室留言翻成台灣慣用繁體中文。三個條件都成立才翻：設定開著、聊天室面板開著、直播語言是外語（自動偵測要等偵測到外語）。
  開關：設定框的「聊天室翻譯」（按儲存當場生效），或膠囊選單「聊天室翻譯：開／關」（當場生效，並寫回 config.json）。
  顯示：留言先不出現，等它那一批的譯文回來，原文（淡色）與譯文（「↳ 譯文」較亮）一起出現，不會先出原文再補譯文而閃動；
        大約晚 4～12 秒，最多 20 秒一定出現（API 很慢時以原文出現）。被跳過、被抽樣略過的留言照原本時間順序和前後留言一起出現。
        聊天室翻譯沒在翻（設定關、聊天室面板沒開、中文直播）時，留言照舊立刻出現。
        膠囊選單「面板 → 聊天室 設定 → 只看譯文」：有譯文的留言只顯示譯文。被跳過或沒翻到的留言只顯示原文。
  不翻的留言：草、www、888、單一字元重複、純數字、固定短語（はい、おつ…）、純表情代碼（Twitch 表情）、純符號；
        外語直播中全漢字的留言當作該外語（例如「全然大丈夫」會翻）。
        不翻不是壞掉：每場第一則不翻的留言出現前，聊天室面板先出現一行說明（哪些留言不翻、直接顯示原文）；
        日文 VTuber 台的聊天常常大半是自訂表情（□）和草，這時看到的大多是原文。結束訊息另外寫「幾則不需要翻」。
        翻譯失敗（呼叫出錯、讀不出譯文、則數對不上）時聊天室面板也說明一次，那幾則只顯示原文。
  批次與上限：最多等 8 秒或累積 40 則送一次；每分鐘最多翻 chat_translate_max_per_min 則（預設 30），熱門台超過就平均抽樣，沒抽到的只顯示原文。
  不拖慢字幕：聊天室翻譯有自己的佇列與背景執行緒，和逐句翻譯完全分開；碰到 API 速率限制（429）就暫停 60 秒、不重送；
        排隊超過 20 秒還沒送的留言放棄翻譯。翻譯失敗一律只顯示原文。
        啟動里程碑紀錄會記下第一則聊天留言、第一批聊天翻譯送出（等了幾秒）與回來（API 花幾秒）、第一則聊天顯示，方便查延遲。
        logs\聊天室翻譯紀錄.txt：每次失敗一行（錯誤類型或 stop_reason；讀不出譯文時附模型回答前 300 字），
        每場結束一行統計（送翻、已翻、失敗、各種不翻原因的則數、每批 API 秒數平均與最大；一則的批次正常約 1～2 秒）。不含金鑰。
  迷因：提示詞裡有固定對照（草→笑死、888→拍手、乙／おつ→辛苦了、てぇてぇ→好貼…），對照表在 chat_translate.py 的 迷因對照，之後要加改那裡；
        不認得的梗保留原文，不硬翻、不解釋。
  費用另外計：狀態列「聊天翻譯」藥丸（開著或用過才出現）、膠囊滑鼠提示、結束訊息都會分開顯示次數與費用。
        啟動面板總費用、ⓘ 比較表、設定框費用表多一項「聊天室翻譯」（以中等聊天量估算，約 $0.02／小時；熱門台有上限封頂約 $0.03／小時；都是估算，照 Haiku 5.5 官方單價 0.10／0.50，2026-10-13 查）。

按「停止」後（2026-10-15 起）：音訊擷取、轉錄、聊天室馬上關掉；正在等的那一輪話題判斷不等了（它的分鐘摘要就不要了），直接整理最後一個話題。
  收尾都在背景做，畫面照常可以操作：停止鈕顯示「整理中… N 秒」，主控台提示條與膠囊旁顯示「已停止擷取與轉錄。正在整理最後的話題摘要…」
  （開了上網查證、還有沒查完的，接著顯示「正在等上網查證收尾…」），膠囊的滑鼠提示也有這一行和已經過的秒數。
  收尾有時間上限：按停止後最多 90 秒（live_topics.收尾上限秒；最後話題摘要與上網查證共用，上網查證另外最多 30 秒）。
  超過上限：已有的內容照樣存檔，來不及的那一題在話題摘要裡留一題「（摘要無法顯示）…內容請看直播稿」，
  結束訊息與膠囊旁提示說明哪一部分沒完成（例如「話題（2:03:43 - 2:06:43）的摘要」「上網查證還有 2 個名詞沒查完」）。
  收尾中按膠囊或系統匣的「結束程式」會先問「摘要還在整理中，確定要結束嗎？」：取消就繼續等；確定就不再等，
  沒整理完的那一題同樣記成「結束程式時這一段還沒整理完」，其他已完成的直播稿、聊天室、摘要都已存檔，然後關閉程式。
  完成後膠囊旁出現幾秒後自動消失的小提示（「已結束」，有存檔時「已結束，已存檔」），不再跳彈窗。

字幕速度（config.json 的 subtitle_speed，預設 "balanced"；沒有這個欄位也當作平衡、不跳警告）：
  在「字幕出得快」與「轉錄比較準、翻譯比較省」之間選一個段位：
    "fast"     速度：分段 8 秒，翻譯批次最多等 1 秒或累積 8 句
    "balanced" 平衡：分段 12 秒，翻譯批次最多等 1 秒或累積 8 句
    "accurate" 準度：分段 20 秒，翻譯批次最多等 8 秒或累積 8 句
  分段越短第一句越早出現，但句子比較常被切斷、偶爾有辨識錯誤；分段越長越穩，翻譯呼叫次數也越少。
  各段位的整體字幕延遲與準確度：速度＝翻譯字幕約慢 8 秒、偶爾斷句錯字；平衡＝約慢 11 秒、準確度佳（建議）；準度＝約慢 18 秒、最準最省錢。
  啟動面板第二行與設定框的「每小時費用」表，依 config.json 目前的單價，估算每小時總費用與各功能（字幕翻譯、換話題判斷、分鐘摘要、話題摘要）各花多少；
  沒開的功能（逐句翻譯面板沒開、中文直播、分鐘摘要關閉）顯示「未開啟 $0」且不計入。金額是估算，實際以 API 帳單為準。
  啟動面板語言旁的「速度／平衡／準度」只影響這一場，不寫回 config.json；下次打開啟動面板會回到設定框的預設。
  一律下次開始生效：啟動中與直播中不能切換（分段長度在一場直播中固定，中途改會讓時間戳錯位）。
  每次開始時，logs/啟動里程碑 檔的開頭會記下段位、分段秒數與翻譯批次。

支援的直播平台與網址（啟動面板、主控台的網址欄；欄內的提示文字是「貼上 Twitch 頻道或 YouTube 直播網址」，滑鼠移上去有完整範例）：
  Twitch：頻道網址，例如 https://www.twitch.tv/頻道名稱（直播檔 /videos/ 不支援）。
  YouTube：公開的「直播」網址，下面這些格式都可以（查到的頻道是同一個，名詞清單也共用同一份）：
    https://www.youtube.com/watch?v=影片代碼        https://youtu.be/影片代碼        https://www.youtube.com/live/影片代碼
    https://www.youtube.com/@帳號/live（或 @帳號）     https://www.youtube.com/channel/UC…（可加 /live）
    https://www.youtube.com/c/名稱、/user/名稱（可加 /live）     https://www.youtube.com/embed/影片代碼    手機版 m.youtube.com
    不支援：/shorts/ 短影片、錄好的影片（VOD）、會員限定與年齡限制的直播。
  YouTube 的已知限制：
    1. 只支援公開的直播；會員限定、年齡限制、需要登入才能看的直播開始時會用白話說明原因。
    2. 聊天室只抓得到「熱門聊天」（YouTube 預先篩選過的留言），不是全部留言。
    3. YouTube 可能要求登入驗證（判斷這台電腦是機器人）：開始時會顯示白話說明，使用者自己無法排除，稍後或換網路再試。
    4. 中途斷線重連過的直播，時間（開播時間起算）可能和 YouTube 重播的進度條差幾分鐘。
    5. 24 小時不停播的直播（開播超過 24 小時）：時間改從開始擷取起算（前面加 +），開始時顯示的是連續直播的說明，不是出錯。
    6. 純音樂的直播沒有人說話，轉錄可能出現幻聽的單字（模型把雜音聽成話）；這是語音辨識的特性，摘要請當參考。
  Super Chat：留言前面加「【SC】」；沒有文字的 Super Chat（「【SC】（沒有留言）」「【SC】貼圖」）不送翻譯，直接顯示原文。

直播時間（直播網址模式）：
  直播稿、逐句翻譯、聊天室、分鐘摘要、話題摘要的時間都是「直播實際進行時間」（例如 1:23:45；Twitch 和重播的時間軸一致，YouTube 從開播時間起算），不是軟體啟動後多久。
  開播時間：按開始時和開播檢查同時查（Twitch 網頁公開資料為主，頻道網頁備援；不需要金鑰、不用第三方服務；每次 3 秒逾時，按「結束」可中斷）。
  換算：句子 = 第一段音訊的直播時間 + 音訊秒數；聊天室留言 = 收到時刻 − 開播時間 − 串流延遲（約 11 秒，和直播稿對齊）。誤差約 ±3～5 秒。
  廣告被濾掉或斷線造成音訊少一段時，會自動把之後的時間往前補（只往前、不倒退），並顯示一行提示。
  YouTube 直播：開播時間、直播主、標題、分類讀 YouTube 觀看頁（不需要金鑰）；音訊一樣用 streamlink（沒有純音訊時抓最低畫質）。
    句子的時間直接用串流片段的時間戳（HLS 的 PDT，直播端的實際時刻）算：第一段音訊的直播時間 = 該片段的 PDT − 開播時間，不靠估計的延遲。
    讀不到時間戳才扣除估計的串流延遲 20 秒（2026-10-14 量 9 個直播：一般延遲 18.5～24 秒、低延遲 10.4 秒；只當備援，誤差可能到 10 秒）。
    聊天室（第 3 步，yt_chat.py）：用 yt-dlp 的 live_chat（免登入、免金鑰），在程式內的背景執行緒呼叫（不另開 python 程序，
      之後打包成 .exe 也能用）。yt-dlp 把留言寫進系統暫存資料夾的「直播摘要_YT聊天室_…」，程式每 0.5 秒只讀新增的部分，
      這一輪結束（包含出錯、按停止）後刪掉；按停止後 5 秒內收尾（網路卡住時 yt-dlp 在背景自己結束，不擋程式關閉）。
      時間 = 留言的發送時刻 − 開播時間（發送時刻本身就是直播端的時刻，不扣串流延遲）；抓不到開播時間時 = 發送時刻 − 第一段音訊的時間戳，
      和直播稿同一個起點。觀眾是看著約 20 秒前的畫面留言，所以留言會比它回應的那句話晚一點（只差反應時間），這是正常的。
      剛連上時 YouTube 會先送一批之前的留言：發送時刻早於開始擷取的不收。
      內容：YouTube 表情拿掉；只有表情的留言保留表情本身（自訂表情顯示 □），聊天室翻譯當純表情不翻。
            Super Chat／Super Sticker 前面加「【SC】」（貼圖沒有文字寫「【SC】貼圖」）。會員加入、置頂訊息等系統訊息不算留言。
            機器人（Nightbot、Fossabot、StreamElements、Streamlabs，以及名字以 bot 結尾的）和「!」開頭的指令照 Twitch 的規則過濾；Twitch 的名單不變。
      抓不到：重試 3 次後主控台與膠囊旁顯示「YouTube 聊天室暫時抓不到（可能是 YouTube 改版），摘要和字幕照常；更新程式後可能會恢復。」
    連續直播（24 小時不停播的頻道）：開播時間是好幾天甚至好幾年前，照算會變成好幾萬小時。
      開播超過 24 小時就當作連續直播：時間改從開始擷取起算（前面加 +，和「抓不到開播時間」同一套），主控台說一行，
      直播稿和聊天室從同一個時間點算起；存檔開頭寫原本的開播時間。
    已知限制：中途斷線重連過的直播，時間（開播時間起算）可能和 YouTube 重播的進度條差幾分鐘（2026-10-14 實測有差 2～5 分鐘的）。
    詞庫與檔名：詞庫用頻道 ID（詞庫/YT_頻道ID.txt），watch?v=、youtu.be、@帳號 等各種網址都用同一份；查不到頻道 ID 時這一場不使用詞庫（主控台說一行）。
      直播稿、聊天室、摘要、逐句翻譯、音訊的檔名開頭用 @帳號（沒有就用頻道 ID，再沒有用影片 ID）。
    已知限制：YouTube 聊天室只抓得到熱門聊天（YouTube 預先篩選過的留言），不是全部留言。
    開播檢查的錯誤會用白話說明：要求登入驗證（被判定成機器人）、直播還沒開始（附預定時間）、會員限定／年齡限制／需要登入（第一版不支援）、錄好的影片（只支援直播）。
  時間格式：未滿 1 小時 mm:ss，滿 1 小時 h:mm:ss（timefmt.py 是唯一來源）。
  抓不到開播時間：時間改從開始擷取起算並在前面加「+」（例如 [+12:34]，存檔與模型也一樣），狀態列時間藥丸變黃並寫「抓不到開播時間」，
                  開始時膠囊旁提示一次，分鐘摘要與話題摘要卡片自動顯示「幾分鐘前」。
  時間顯示（config.json 的 time_display："stream" 直播時間（預設）、"ago" 幾分鐘前；舊的 config.json 沒有這個欄位也當作預設、不跳警告）：
    只影響分鐘摘要與話題摘要卡片；直播稿、逐句翻譯、聊天室一律顯示直播時間。設定框（按儲存）或膠囊選單「時間顯示」切換，當場生效。
    「幾分鐘前」每分鐘更新一次（分鐘數變了而且看得到才重畫）。
  直播主、標題、分類：只顯示在膠囊滑鼠提示與各存檔開頭（「# 」開頭的幾行；文字稿模式重讀時會略過），不放狀態列、不送給模型。
  待辦：直播主斷線後重新開台時，開播時間會變，目前不會重新查（下一場重新開始即可）。

啟動時間里程碑紀錄：每次按「開始」，會在 logs/啟動里程碑_日期_時間.txt 記下各階段（模型載入、第一段音訊、第一段轉錄、第一句翻譯、第一句顯示）從按下開始起算的秒數，不含金鑰。
面板（分鐘摘要、話題摘要、逐句翻譯）還沒有內容時，會依階段顯示「載入模型中…／聆聽中，等待第一段…／轉錄與翻譯中…」，第一句出現後消失。

狀態列的「語言」藥丸：一直顯示目前語言（例如「語言：日文（自動偵測）」「語言：日文（手動）」，自動偵測中顯示「偵測中…」）。
語言設為自動時，旁邊有「重新偵測」鈕（膠囊選單也有，固定在「開始…／停止」下方）：不中斷直播，用下一段有人聲的音訊重新判斷。信心低於 0.4 時，第一次會退回中文並明確標示「偵測不確定」；重新偵測低信心則維持原語言。
主控台收著時也看得到語言警告：偵測不確定或失敗時，膠囊上多一段黃色「⚠ 語言」（燈色不變），膠囊旁跳出約 8 秒的提示；
膠囊與系統匣的滑鼠提示也會顯示目前語言。重新偵測成功或按停止後，「⚠ 語言」就消失。
錯誤提示：直播中途的錯誤（例如金鑰失效）、config.json 的設定警告，除了主控台的提示條，也會在膠囊旁用紅框中文提示約 12 秒。
啟動中的錯誤（網址錯誤、沒開播）照舊顯示在啟動面板裡。

話題切分的做法（live_topics.py；2026-10 調整，之後用實際直播驗證，不再用 VOD 調整切分邏輯）：
  目標：「一件事一題」是主要的切法，15 分鐘上限（max_topic_min）只當保險；最短 3 分鐘（min_topic_min）。
  1. 錨點：每個話題在開始時定下「那一件事」（10～20 字，模型的 topic 欄位），之後不改寫；每輪（check_minutes，預設 1 分鐘）判斷新文字是不是還在聊這件事。
     原因：以前拿每輪改寫的簡述比對，簡述會吸收新內容，話題漂移後永遠判「延續」，模型很少回 new_topic。
     簡述（topic_brief）仍每輪更新，只給介面顯示，不參與判斷。提示詞不含話題已進行多久、不含話題長度或標題。
  2. 換話題規則（換話題規則，live_topics.py）：一個話題＝一件事；算 new_topic、算 same 的條件都寫在裡面；沒有跟任何直播內容有關的例子。
  3. 被最短分鐘數擋掉：模型判 new_topic 但話題還沒滿 min_topic_min（或切點對不上稿裡任何一行）時，不切話題，但錨點換成新的那件事，
     之後的輪次跟新的事比對（否則新的事會一直被當成舊錨點的延續）；話題開始時間不動（那些行確實在這一題裡）。
  4. 錨點只能是一件事：提示詞要求不可用「與」「、」「及」「並」串接；引擎再保一道（單一主題()）：遇到 與／与／及／並／并／、／／／斜線／逗號 等，只留第一件
     （第一件短於 2 字就原樣保留；「和」「跟」不切）。
  5. 打招呼、感謝訂閱或贈禮、念聊天室留言不能當錨點，也不能成為被擋時換上的新錨點：提示詞禁止，引擎用關鍵字再擋一次（是雜訊主題()，關鍵字在 雜訊主題）；
     這類 topic 當作沒給，保留原本的錨點（話題剛開始還沒有錨點時，等下一輪有正常的事再定下）。
  6. 話題摘要的標題：只寫這一題最主要的那一件事，不用「、」「與」「並」「及」串接，次要內容放在【摘要】內文（話題格式 的【話題標題】那一行）。
  7. 話題摘要拿不到內容時（live_topics.py 的 問話題摘要）：卡片標題「（摘要無法顯示）」，【摘要】依原因分開說明，不全部說成「沒有照格式」：
     空回應（沒有任何文字）自動重試一次，重試時關閉延伸思考——最常見的原因是思考把回覆長度上限（llm.MAX_TOKENS，2026-10-15 起 8000，原本 4000）用光、還沒寫出文字
     （2026-10-15 實測 Haiku 5.5 正常一題約用 2,700 token）；重試仍空白就說「用完了回覆長度上限」或「回傳空白」並註明已重試。
     模型拒絕（stop_reason=refusal）不重試，說「拒絕回覆」；伺服器錯誤等呼叫出錯（SDK 已自己重試過）只讓這一題顯示錯誤類型，不中斷整場；
     金鑰、連線問題照舊停下整場。有文字但找不到格式才說「沒有照格式回覆」。
     逾時與重試上限（2026-10-15 起，llm.摘要逾時秒、llm.摘要最多重試）：摘要類呼叫（話題判斷、分鐘摘要、話題摘要）每次最多等 180 秒、SDK 最多再重試 1 次，
     API 卡住時最久約 6 分鐘就放棄這一輪（原本沒設，SDK 預設單次 600 秒再重試 2 次，最久將近 30 分鐘）。180 秒在延伸思考開著、寫滿 8000 token 時也夠。
     逾時不當成連線問題、不停下整場：話題判斷這一輪當作話題沒變（same），話題摘要顯示「呼叫模型時出錯（APITimeoutError）」，下一輪照常。
     逐句翻譯、聊天室翻譯、上網查證各有自己的設定，不受影響。
     費用：重試只在空回應時發生，多一次呼叫約 $0.0003～0.0025（Haiku 5.5；輸入約 3,000 token，關閉思考後輸出通常幾百 token）。
     logs\摘要格式紀錄.txt 每筆附 stop_reason、拒絕類別、輸入／輸出 token、內容區塊種類，出錯時附錯誤類型（不含金鑰）。
  已知限制：
  - 模型判斷「一件事」的粒度不穩定：有時把同一件事判成換題（買手機→買新手機）、有時把幾件事放在同一題；同一場直播的結果也會因模型回答不同而略有出入。
  - 短於 3 分鐘的話題會被併入前一題（被擋掉的那件事沒辦法獨立成題）；3 分鐘下限由 min_topic_min 決定，沒有放進提示詞。
  - 被擋時錨點若換成很細的小事，之後可能長時間判 same，直到撞上 15 分鐘上限。
  - 標題是模型寫的，規則只在提示詞裡，沒有引擎檢查，仍可能出現串接。
  - 雜訊主題的關鍵字比對很簡單，極少數正常主題剛好含「訂閱」「感謝」之類的字時，會被當成沒有錨點。
  重跑與對照：開發用 VOD 轉錄與重播的做法見下一段；每次調整後的數字（題數、撞上限次數、費用）在對話紀錄裡，沒有另外存檔。

摘要的說話者（live_topics.py 的 說話者規則；換話題判斷／分鐘摘要、話題摘要、支線的提示詞一律附上，分鐘摘要關掉時也有）：
  語音稿沒有標示誰在說話，摘要照下面三條寫：
  1. 預設語音稿是實況主一個人在說，照常寫「實況主」；沒有明確證據顯示有第二個人在說話時，不改成「有人提到」。
  2. 稿裡出現的人名預設是「被提到、被呼喊的人」，不是說話的人：不可當句子主詞去描述說話內容，也不可推論「實況主就是某某」。
     實況主對某個對象（人、寵物、角色、觀眾）用「你」說話時，句子描述的是那個對象，不是實況主自己。
  3. 稿裡有多人的線索才對看不出是誰說的句子用「有人提到」「對話中提到」這類中性說法。線索：明顯的一問一答或有人回應實況主、
     提到正在連線／通話／合作、同一段出現不同的自稱或語氣；問句後面緊接「うーん」「はい」這類很短的回答時，前後文也像對話才算。
     實況主對聊天室、寵物、觀眾說話不算多人線索。
  已知限制：
  - 只靠文字稿分不出說話者：上面都是請模型從字面猜，猜錯時仍可能把別人的話算到實況主（或反過來把實況主自己的話寫成「有人」）。
  - 合作直播中，對方話少時仍可能被算到實況主；對寵物說的話、一問一答的短答也可能判錯。
  - 真正的解法要等之後的說話者分離（在轉錄階段分出誰在說話），現在的提示詞只是緩解。
  - 直播主名稱、標題、分類仍不送給摘要模型（只送給上網查證）。

直播主專有名詞詞庫（glossary.py；一律開著，沒有 config.json 欄位）：
  用途：讓同一個直播主的人名、作品名、遊戲名、地名、梗名在摘要裡寫法前後一致（這一場之後的摘要、下一場都沿用）。詞庫本身不上網、不增加模型呼叫次數（上網查證另見下一段，預設關）。
  放哪：%LOCALAPPDATA%\LiveSummary\詞庫\直播主.txt（本機檔案，不進 git）。檔案不存在就當作空的，第一次自動加入名詞時才建立。
  哪個直播主：直播網址模式用頻道名稱（網址最後一段，例如 https://www.twitch.tv/abc → 詞庫/abc.txt）；
            文字稿模式用 --streamer 指定，例如  python live_topics.py 稿.txt --lang ja --streamer abc
            沒給 --streamer（或從介面用文字稿重播）就不讀、不寫詞庫，其他照舊。
  格式：UTF-8 純文字，每行一個名詞「中文寫法｜原文｜來源」，例如
            艾連｜エレン｜手動
            米卡莎｜ミカサ｜候選
        來源有五種（上網查證的詞條會多第 4 欄，見後面「上網查證」那一段）：
          手動：你自己填的，每一場都提供給摘要；程式永遠不會改動或刪除。中文直播的名字可以只寫「中文寫法」；沒寫來源的行也當作手動。
          候選：話題摘要自動加入的。只在加入的那一場提供給之後的摘要使用，下一場起讀進來但不提供給摘要（模型可能編錯字，不讓它一直被沿用）。
          自動：舊版詞庫檔用的來源名稱，一律當作候選處理，檔案內容不改寫。
          上網：上網查證確認過的寫法（最後一欄是來源網址），和手動一樣每一場都提供給摘要。
          忽略：在名詞清單按了「刪除」的名詞，不提供給摘要，也不會再被自動加入或上網查證（見下面「名詞清單」）。
        「|」半形全形都可以；「#」開頭的行是說明。格式不對的行（欄位太多、來源不認得、沒有寫法）會略過不用，但檔案裡保留原樣。
  手動加／刪：最簡單是用介面的「名詞清單」（見下一段）；也可以用記事本打開，照格式加一行（例如先把成員名、作品名填進去）；不要的整行刪掉；存檔用 UTF-8。下次開始時生效
        （直播中改的，下一次自動加入名詞時也會讀到）。手動的行程式永遠不會改動或刪除。
  把候選升級成手動：看過候選的寫法沒問題，就把那一行最後的「候選」（或舊檔的「自動」）改成「手動」，存檔；下一場開始就會提供給摘要。
        寫法不對就直接改正或刪掉那一行。
  運作：開始時讀入並印「已載入詞庫：直播主，手動 N 個（另有候選 M 個，這一場不使用）」（沒有候選就不印括號）；每一輪換話題判斷（含分鐘摘要）與每次話題摘要的提示詞附上詞庫，
        最多 30 個（手動的優先，其次是稿裡出現的、這一場最近用到的、較晚加入的）；沒有可提供的詞條（空的、或只有候選）時提示詞不出現這一段。
        要求模型：稿裡出現詞庫中的名字時沿用詞庫寫法；稿裡沒提到的不可因為詞庫有就寫進摘要；詞庫沒有的照原本規則；
        使用詞庫的名字時一律「中文寫法在外、原文在括號裡」，不可反過來，詞條沒有原文就只寫中文。
        話題摘要那一次呼叫順便在最後一行列出【名詞】（只列有把握的，「不確定」的不列）；這一行不會顯示、不會存進話題摘要檔。
        自動加入的條件：原文（沒有原文就看中文寫法）真的出現在這一題的語音稿裡（模型常把詞庫整串抄進清單，稿裡沒提到的不收）；
        中文寫法裡不能有假名或日文字形（例如 弾、鉄）；模型寫反成「原文（中文）」時自動對調；詞庫裡還沒有這個原文。
        符合的接在檔案最後（來源「候選」），並印「詞庫新增：…」。每次寫檔先寫暫存檔再取代，寫到一半失敗原檔不會壞。
        詞庫檔讀不懂（例如不是 UTF-8）時印一行提示，這一場不使用也不寫入，原檔不動。
  已知限制：
  - 詞庫只保證寫法一致、不保證正確：第一次寫錯的名字（例如翻譯不準），之後會一直沿用同一個錯的寫法。
  - 轉錄（Whisper）就聽錯的名字救不了：詞庫只能比對稿裡已經寫出來的原文。
  - 候選是模型寫的，可能有錯字或編出來的音譯；它只在加入的那一場使用，之後不會被沿用，所以不用特地清。
    但也因此沒升級成手動的名字，下一場寫法可能又不同；常出現的名字請檢查後改成「手動」。
  - 模型只願意寫假名、沒給中文寫法的名字（例如 VTuber 的暱稱）不會自動加入，寫法仍可能前後不一；這類名字請手動加（例如「曼太郎｜マン太郎｜手動」）。
  - 模型偶爾把一般詞彙（食物、日用品）也列成名詞，會被收進詞庫成為候選；看到就刪。
  - 「最近用到」只記在這一場裡；手動詞條超過 30 個時，只放稿裡出現的與較晚加入的，其餘不會放進提示詞。
  - 使用詞庫名字時括號方向（中文在外）是提示詞要求的，模型偶爾仍會寫反，引擎沒有檢查。

名詞清單（names_page.py；在介面上訂正詞庫的名字寫法，不用打日文、不用開記事本）：
  入口：
    - 膠囊／系統匣選單的「名詞清單」（在「設定」上面）：直播中是這一場的頻道；待命時是啟動面板網址欄的頻道。
    - 啟動面板網址欄下方的「名詞清單」按鈕：照網址欄目前的頻道打開，開始前就能先替這位直播主填好名字。
    - 網址欄還不是 Twitch 頻道網址或 YouTube 直播網址（空白、VOD 網址、其他網站）時，按鈕和選單項目都停用，旁邊／括號裡寫出原因；
      從介面用文字稿重播時沒有直播主，選單項目停用並寫「文字稿重播沒有指定直播主」。
  視窗：獨立視窗（和設定框同一種深色卡片風格）。
    上方表格五欄：原文（程式帶入，不能改）｜顯示寫法（雙擊修改）｜來源｜這一場｜網址。
      來源用白話顯示：你填的（手動）、上網查到（上網）、自動找到・未確認（候選）、自動找到・上網查無（候選・已查）。
      這一場：直播中，這一場的語音稿裡出現過的名詞標「●」，並排在最前面；待命時這一欄是空的。
      網址：上網查到的名詞有「打開來源」連結，點了用瀏覽器打開。
    表格下方：「確認寫法」「刪除」（對選到的那一行）、「重新整理」。
    再下面「新增名詞」：顯示寫法（必填）、原文（選填，知道原文的人可以貼上）、「新增」。
    最下面是狀態文字，右下角有給進階使用者的小連結「用記事本打開」。
  操作（每個動作都立刻存檔，不用另外按儲存）：
    - 改顯示寫法：可以填中文，也可以填羅馬拼音或英文（例如 Mantarou）。改了那一行就變成「你填的」（手動），原文不變。
    - 確認寫法：寫法沒問題就不用改字，直接把「自動找到」或「上網查到」變成「你填的」，之後每一場都會使用。
    - 刪除：要再按一次確定。刪掉的名詞不會真的從檔案刪除，而是那一行的來源改成「忽略」：清單不顯示、摘要不使用，
      之後話題摘要再列出同一個原文也不會被自動加回來，上網查證也不會查它。
      想讓被忽略的名詞恢復：用記事本打開，把那一行（最後一欄是「忽略」的）整行刪掉存檔；
      或在「新增名詞」填同一個原文，就以新增的這一筆（你填的）為準，忽略的那一行會被換掉。
    - 新增：只填顯示寫法也可以（中文直播的名字、或不知道原文時）；同一個名詞已經在清單裡時不會重複加，請直接改那一行。
  什麼時候生效：存檔後立刻生效。直播中改的是這一場正在用的詞庫，下一輪的換話題判斷、分鐘摘要、話題摘要就用新寫法；
        已經顯示過的摘要不會回頭改。待命時改的，下一次開始時使用。
  提示詞的例外：詞庫的顯示寫法要照原樣使用，即使是羅馬拼音或英文，也不受「正文不可夾雜英文單字」的限制，
        格式一樣是「顯示寫法（原文）」，例如「Mantarou（マン太郎）」。這個例外只限詞庫裡的名字；其他英文單字、日文照原本規則。
        沒有詞庫（或詞庫是空的）時，提示詞和原本完全一樣。
  自動更新：視窗開著時每秒檢查一次，話題摘要加入新的候選、上網查證查到結果、或用記事本存檔後，清單自動更新；
        正在編輯某一格時不會打斷、也不會清掉正在打的字，等編輯完才更新。
  和記事本同時改：每個動作都先重讀檔案、只改那一行，別的行（包含記事本剛改的）原樣保留；
        和話題摘要的自動加入、上網查證共用同一把鎖，同時寫不會互蓋。
        如果要改的那一行剛被記事本改過（或刪掉），不會蓋掉記事本的修改：視窗顯示「這一行剛在別處被改過」並重新載入，請再操作一次。
  詞庫檔格式多一種來源「忽略」，例如  蛋白粉｜プロテイン｜忽略
  已知限制：
  - 名詞清單的寫法只影響摘要（換話題判斷、分鐘摘要、話題摘要），不影響逐句字幕翻譯與聊天室翻譯。
  - 顯示寫法是羅馬拼音時，模型偶爾仍可能改寫成中文或片假名，或把括號寫反；提示詞有要求，引擎沒有檢查。
  - 只能改顯示寫法，不能改原文；原文寫錯（轉錄錯字）時，請用「新增」填正確的原文，再把錯的那一行刪除。
  - 一個直播主一份清單，不能跨直播主共用；不能在摘要文字上直接點名字修改，也不能回頭改已經顯示的摘要。
  - 「這一場」欄只在直播中標示，判斷方式是原文（沒有原文就看顯示寫法）有沒有出現在這一場的語音稿裡。

上網查證詞庫的候選名詞（web_verify.py；config.json 的 web_verify，預設關）：
  用途：話題摘要自動加入的「候選」常寫錯（音譯亂編、日文字形、轉錄錯字）。打開後，用 Claude 官方的上網搜尋工具查證候選：
        查到有可靠來源的台灣通行寫法 → 那一行改成「上網」，最後一欄附來源網址；之後的摘要與下一場都會使用（和手動一樣）。
        搜尋過、找不到可靠寫法 → 保持候選，最後一欄標「已查」，之後不再查（避免重複花錢）。
        不直接改摘要內容；摘要變好是透過詞庫。
  開關：設定框「功能與模型」的勾選「上網查證詞庫的候選名詞：查到台灣通行寫法就寫回詞庫並附來源網址（只支援 Claude，另外計費）」（下次開始生效）；
        命令列 --web / --no-web 臨時覆蓋；--show-config 會列出 web_verify 與來源。舊的 config.json 沒有這個欄位就當作關，不會警告。
  只支援 provider = anthropic（Claude 的 web_search 工具）。openai_compatible（OpenAI、DeepSeek、Ollama）開始時會印
        「上網查證無法使用：…這一場不查證，其他功能照常。」，其他照常跑。
  什麼時候查：直播中只查「這一場新加入的候選」：話題摘要加入候選後丟給背景執行緒查，不等結果，所以不會拖慢字幕、換話題判斷與分鐘摘要
        （實測主執行緒只多了把名詞放進佇列的時間，微秒等級；寫回詞庫時兩邊共用一把鎖，最多等一次寫檔，毫秒等級）。
        每場最多查 10 個（web_verify.每場上限）；超過的保持未查。以前留下、還沒查過的候選，直播開始時不會自動查，請用下面的小工具。
        每個名詞最多搜尋 2 次（web_verify.每詞最多搜尋）。查證模型＝config.json 的 model。
  查證給模型的脈絡：名詞原文、摘要模型給的中文寫法、直播主、直播分類／遊戲與標題（直播網址模式才有；文字稿模式是「不明」）、稿裡出現這個名詞的前兩句。
        要求：只接受有可靠來源支持的台灣通行寫法（官方譯名、台灣代理商、台灣媒體、中文維基百科等），找不到就回「查無」，不可自己翻譯或音譯。
  程式另外再擋：
        - 網址必須是上網搜尋工具真的回傳過的（搜尋結果或引用裡出現過）；模型自己打出來、搜尋結果裡沒有的網址，一律當作查無。
        - 查到的寫法裡有假名或日文字形（例如 鉄）、太長、有「｜」，當作查無。
        - 「沒查成」和「查無」分開：逾時、API 錯誤、速率限制、回答被截斷、模型根本沒搜尋成功、回覆看不懂 → 什麼都不改（不標已查），下次還能再查。
        - 結束（或按停止）後最多等 30 秒（web_verify.收尾等待秒；按停止時還要扣掉整理最後話題已用掉的時間，兩者合計不超過 90 秒）讓背景查完；沒查完的保持未查，時間到之後才回來的結果也不寫回。
  詞庫格式多一個可省略的第 4 欄（舊的三欄檔照常讀）：
            呼拉圈｜フラフープ｜上網｜https://zh.wikipedia.org/zh-tw/...
            DX日輪刀｜デラックス日輪刀｜上網｜https://www.4gamers.com.tw/... 正式原文：DX日輪刀
            稻妻11｜稻妻イレブン｜候選｜已查
        原文欄保留稿裡（轉錄）的寫法，才比對得到之後的語音稿；搜尋發現原文本身寫錯時，正確的原文記在網址後面「正式原文：…」。
        手動的詞條程式永遠不改；同一個名詞已有手動（或上網）的，候選那行也不查、不改。上網的不再查。
        想重查一個「已查」的候選：把最後的「｜已查」刪掉存檔。覺得上網的寫法不對：直接改正並把來源改成「手動」，或刪掉那一行。
        寫回時沿用詞庫的安全寫法（暫存檔再取代）與「存檔前重讀」，並和話題摘要的自動加入共用一把鎖，兩邊同時寫不會互蓋。
  開始時「已載入詞庫」那一行會分開列手動與上網的數量，例如「已載入詞庫：abc，手動 3 個、上網 7 個（另有候選 5 個，這一場不使用）」。
  結束訊息多一行，次數與費用和摘要分開：
        上網查證：查 N 個，確認 X 個，查無 Y 個，未完成 Z 個；呼叫 n 次，搜尋 s 次，輸入／輸出 token；估算費用（token 與搜尋費分開列）
  費用：搜尋每 1,000 次 10 美元（官方文件，2026-10-13 查證），搜尋出錯不收費；另加 token（搜尋結果算輸入 token，每個名詞約 2 萬）。
        token 的金額照 config.json 的 price_input／price_output（預設是 Haiku 5.5 官方單價，見上面的說明）。實測（Claude Haiku 5.5，14 個名詞）：每個名詞平均搜尋 2.0 次、
        輸入 21,244／輸出 611 token；照官方單價（Haiku 5.5 每百萬 token 輸入 0.10／輸出 0.50 美元）每個名詞約 0.0224 美元，
        其中搜尋 0.020、token 0.0024——費用幾乎都是搜尋費。設定框的費用表多一列「上網查證」（以每小時 10 個名詞估算，約 $0.22／小時；
        其餘各項照官方單價約：字幕翻譯 $0.02、聊天室翻譯 $0.02、話題追蹤 $0.01、分鐘摘要 $0.01、話題摘要 <$0.01，合計約 $0.28／小時）。
  開發／整理詞庫用的小工具（會花 API 費用，只支援 anthropic）：把指定直播主詞庫裡所有還沒查過的候選查一遍，不跑直播、不做摘要：
        python scripts/verify_glossary.py 直播主 --transcript 稿.txt [--max 10] [--category 分類] [--title 標題]
        --transcript 用來找名詞出現的句子（可給多個；沒給就找「文件」\直播摘要 裡的 直播主_*_直播稿.txt）；--max 預設 10，可調。
  已知限制：
  - 可靠來源由模型判斷，網址只保證「真的是搜尋結果」，不保證那一頁真的支持這個寫法；上網的詞條請偶爾點網址確認。
    實測有把一般詞彙（蛋白粉）也查成上網、來源是品牌官網的情況；現在【名詞】與查證兩個提示詞都要求一般詞彙不列／回查無（只靠提示詞，程式沒有過濾）。
  - 轉錄錯得太嚴重（例如 VUタンデート、シンジプー）通常查無；查無的會一直是候選（只在加入那一場使用），常出現的請手動改。
  - 原文被轉錄成錯的字形（例如 稻妻イレブン，正確是 イナズマイレブン）：查證提示詞規定第一次搜尋找不到時，第二次必須換成正確原文或官方英文名搜。
    實測（2026-10-13）稻妻イレブン 第二次改搜 Inazuma Eleven，查到《閃電十一人》（中文維基百科），寫成上網並記「正式原文：イナズマイレブン」；
    但這只測過一個名詞，模型不一定每次都換對關鍵字。查無的已標「已查」，想重查要手動刪掉「｜已查」。
  - 每場上限 10 個：一場新的候選超過 10 個時，多的保持未查，下次用小工具查。

開發者：用 Twitch VOD 測試話題切換與 h:mm:ss 時間格式（開發工具，不是產品功能，不在介面裡）：
   不用看完整場直播：把 VOD 的指定時段轉成直播稿，再用「文字稿重播模式」快轉跑摘要。
   1. 轉成直播稿（只下載該時段的音訊、本機 Whisper 轉錄，不花 API 費用；需要已裝 streamlink、ffmpeg，沒有顯示卡會很慢）：
        python scripts/vod_to_transcript.py https://www.twitch.tv/videos/2898838036 --start 0:06:25 --end 1:30:00 --lang ja
      --start 沒給就從 0 開始，--end 沒給就到 VOD 結尾；--lang 可填 zh、ja、en、ko、auto（自動偵測，用 5 段音訊投票；VOD 開頭是音樂或等待畫面時可能判錯，不確定就直接指定）。
      音訊與直播稿放在 測試素材/（已被 .gitignore 忽略），檔名像 vod2898838036_0h06m25s-1h30m00s_直播稿.txt。
      時間戳是 VOD 內的原始時間（和 Twitch 播放器對得上），超過 1 小時是 h:mm:ss。
      streamlink 只能從 VOD 的分段邊界開始（約 10 秒一段），所以實際起點可能比 --start 晚幾秒；實際起點寫在直播稿開頭「# 」開頭的說明行（重播時會略過）。
      只處理音訊與直播稿，不抓 VOD 聊天室。
   2. 用重播模式跑摘要（會呼叫摘要模型，花 API 費用；設定照 config.json）：
        python live_topics.py 測試素材/vod2898838036_0h06m25s-1h30m00s_直播稿.txt --lang ja --speed 0
      --speed 0 = 不等待、瞬間讀完（最快，實際速度只受 API 回應時間限制）；--speed 60 = 60 倍速；--speed 1 = 真實速度。
      快轉只影響讀稿的等待時間，不影響換話題判斷：判斷是依稿裡的時間（--check 幾分鐘一次）和文字量決定，不看現實時鐘，所以 --speed 0 與 --speed 60 的結果相同。
      文字稿模式不能自動偵測語言，請用 --lang 指定（config.json 的 language 是 auto 時，不指定會照外語說明處理）。
      不從 0:00 開始的直播稿可以直接跑：第一行的時間就是第一輪檢查的起點，話題與摘要的時間都用稿裡的原始時間。
      結果檔（話題摘要、分鐘摘要）會存在直播稿旁邊的 測試素材/（config.json 的 save_summary 開著才存）；也可以用介面的「文字稿」來源重播同一份直播稿（要先在設定框的「開發者選項」勾「顯示文字稿重播模式」）。
   3. 摘要費用估算（用目前單價 Haiku 輸入 $1／輸出 $5、延伸思考關、沒有聊天室、分鐘摘要開，cost_estimate.py 的估算，實際以 API 帳單為準）：
        每小時直播稿約 US$0.24（換話題判斷約 $0.13、分鐘摘要約 $0.09、話題摘要約 $0.03）；1.5 小時約 US$0.37。
      延伸思考開著時輸出約 3.7 倍，費用大約再多一倍以上。

開發環境（Python 3.13，2026-10-14 起；舊的 Python 3.10 不再用於開發，也不再支援）：
   環境放在專案資料夾的 .venv（已被 .gitignore 忽略），套件一律用鎖定檔 requirements-lock.txt 安裝（每個相依套件都是測過的確切版本）。
   1. 建立（新電腦或要重建時做一次；要先裝 Python 3.13：python.org 的 Windows 64 位元安裝程式，不必勾「加到 PATH」）：
        %LOCALAPPDATA%\Programs\Python\Python313\python.exe -m venv .venv
        .venv\Scripts\python.exe -m pip install -r requirements-lock.txt
        git config core.hooksPath .githooks
      （PowerShell 裡 %LOCALAPPDATA% 要寫成 $env:LOCALAPPDATA；或用 py -3.13 -m venv .venv）
   2. 使用：在專案資料夾開終端機，先啟動環境，之後打 python 就是 3.13：
        命令提示字元：.venv\Scripts\activate
        PowerShell：  .venv\Scripts\Activate.ps1
      提示字元前面出現 (.venv) 就是啟動了；關掉終端機就恢復。不想啟動的話，把 python 換成 .venv\Scripts\python.exe 也一樣，例如：
        .venv\Scripts\python.exe app.py
        .venv\Scripts\pythonw.exe app.py        （不開黑色命令列視窗）
   2-1. 隨附的 ffmpeg（和打包版用同一版）：.venv\Scripts\python.exe scripts\下載ffmpeg.py
      下載 BtbN 的 LGPL shared 版月底版 n9.0.2-17（版本、網址、SHA-256 釘在腳本裡；版本選擇原因見 docs/打包調查.md），雜湊不符就拒絕使用），解開到 vendor\ffmpeg（.gitignore，不進 git），
      壓縮檔備份留在 vendor\下載；同時把這一版 FFmpeg 的原始碼備份到 vendor\原始碼\FFmpeg-<提交>.zip（LGPL 要提供原始碼，發布時上傳到發布頁）。程式找 ffmpeg 的順序：vendor\ffmpeg\bin\ffmpeg.exe → 系統上的；用了哪一個寫在 logs\啟動里程碑_*.txt（「找到 ffmpeg」那行）。
   2-2. 打包成 .exe（PyInstaller 6.22.3，已在 requirements-lock.txt；決定與原因見 docs/打包調查.md）：
        .venv\Scripts\python.exe scripts\build_exe.py
      先要有 vendor\ffmpeg（上面 2-1）。設定在 LiveSummary.spec；腳本會清掉舊的、打包、放 LICENSE、驗收（該收的檔案都在、
      helper.exe 列得出 streamlink 外掛）、壓縮，最後印出花費時間與大小。結果：
        dist\LiveSummary\LiveSummary.exe     主程式（無視窗）
        dist\LiveSummary\helper.exe          命令列版，主程式另開 streamlink／yt_audio 用（使用者不用點它）
        dist\LiveSummary\_internal\          共用的程式庫、隨附 ffmpeg（ffmpeg\bin）、cuBLAS（nvidia\cublas\bin）
        dist\LiveSummary-v1.0.0.zip          整個資料夾的壓縮檔（檔名的版本號從 version.py 來）
      build\、dist\ 不進 git。打包版的程式資料與輸出位置和直接跑 app.py 相同（見最上面「檔案放在哪裡」）。
      測打包版一樣要從檔案總管雙擊 LiveSummary.exe，不要從 Claude 桌面版裡啟動。
      從壓縮檔內直接點開 exe 會跳英文錯誤、程式碼來不及攔（開機程式在 Python 啟動前就失敗），所以只靠上面最前面那段說明請使用者先解壓縮；
      試過 C# 啟動器、不採用（原因見 docs/封存/打包調查_已完成紀錄.md「第5步之一結果」）。
   桌機測試（第三階段）：docs\乾淨電腦測試清單.md（給 Ray 照著做、附打勾格子）。強制 CPU 的測試：scripts\強制CPU測試.bat（設 CUDA_VISIBLE_DEVICES=-1 再開程式，
      程式判斷成沒有顯示卡、改用 CPU 與 small 模型）；打包時複製到 dist\（LiveSummary 資料夾外面、不進壓縮檔）。
   版本號：只寫在 version.py（v1 = 1.0.0）。顯示在設定框最下面、logs\當機紀錄.txt、三個 exe 的檔案內容（右鍵 → 內容 → 詳細資料）、zip 檔名；
      其他地方都從 version.py 讀（tests\test_版本號.py 會檢查沒有別處寫死）。改版本只改 version.py 的 版本。
   圖示：assets\icon.ico 放了就套用到三個 exe 和視窗（附進 _internal\assets\icon.ico）；沒放用預設，打包不會失敗。說明見 assets\README.txt。
   第三方授權清單：scripts\licenses.py（打包時自動跑）產生 dist\LiveSummary\licenses\（第三方授權清單.txt 總表＋每項全文），
      只列實際帶進去的套件，加上 Python、PyInstaller、FFmpeg、Intel OpenMP、VC++ 執行階段；總表最後有 LGPL／GPL／MPL 元件的「原始碼取得方式」。
      套件沒附的全文（ctranslate2、tokenizers、Intel OpenMP、Qt 內含的第三方元件）放在 third_party_licenses\（提交進 git，打包不連網），
      由 scripts\取得授權全文.py 從上游取得——套件升級後重跑一次；cuBLAS 聲明、VC++ 說明是那裡的手寫檔。
      打包時印警告（不讓打包失敗）：沒附全文、來源待確認的檔案、*.libs 隨附函式庫沒收錄授權、沒有原始碼網址、third_party_licenses 版本不符。
      單獨跑：.venv\Scripts\python.exe scripts\licenses.py（用現有的 dist、build）。現況與待決定的項目見 docs\封存\打包調查_已完成紀錄.md「授權收尾結果」（目前有效的規則與待辦在 docs\打包調查.md）。
   OpenSSL：打包只用 Python 自己的 libcrypto-3.dll／libssl-3.dll（打包時 PATH 只留 Python 與 Windows 系統資料夾，驗收比對 SHA-256，不同就失敗）。
   使用說明：給一般使用者的 docs\使用說明.txt，打包時放在 zip 最上層。
   系統匣圖示說明：tray_tip.py（首次引導第 3 頁、設定框共用），按鈕打開 ms-settings:taskbar。
   當機紀錄：crash_log.py 攔主執行緒、其他執行緒、Qt 槽函式裡沒被接住的錯誤（以及 Qt 嚴重錯誤、原生層當機時的 Python 堆疊），寫進
      %LOCALAPPDATA%\LiveSummary\logs\當機紀錄.txt（時間、版本號、完整錯誤；超過 2 MB 改名成 當機紀錄.舊.txt），同時跳出中文提示
      （有「打開紀錄資料夾」按鈕；30 秒內不重複跳，紀錄照寫）。寫入前一律遮 API 金鑰：認證管理員與環境變數讀到的整串、sk-…、AIza…、
      Authorization／api_key／token／password 後面的值、32 字元以上的英數長字串。
      程式裡沒有任何使用者能觸發的「測試當機」；測試用的觸發方式只在 tests\test_當機紀錄.py。
   網址欄全形字：注音輸入法會把「_」打成「＿」、「/」「:」「.」變全形；platforms.整理網址() 在解析、按開始前把全形英數字和符號轉半形、去前後空白
      （只轉全形 ASCII 區、全形空白、「。」，中文與日文字不動）。
   另開程序：所有外部程式（streamlink、ffmpeg、nvidia-smi）都經過 external.py 的 開啟()／執行()，統一加 CREATE_NO_WINDOW（無視窗模式不閃黑色視窗）；
      不要在其他檔案直接用 subprocess（tests\test_外部程式.py 會檢查）。打包後 streamlink 改呼叫同資料夾的 helper.exe（進入點 helper.py）。
   3. 確認：python --version 應該是 3.13.x；沒啟動時直接打 python 會是系統上的其他版本（例如 3.10），不要用它跑程式或檢查。
   4. 升級套件：改 requirements.txt → 在乾淨的 3.13 環境裝 requirements.txt 與 requirements-dev.txt → 跑 check.py --all 與真模型實測
      → pip freeze 重新產生 requirements-lock.txt（av 要維持 17.1.0，原因見 requirements.txt）。
   提交前檢查：git hook 固定用 .venv\Scripts\python.exe 跑（找不到 .venv 會擋下 commit 並說明）；check.py 不是 Python 3.13 也會直接失敗並說明。
   之後每次 git commit 會自動跑 pytest 與 ruff（警告數不得超過 .ruff-baseline），沒過就不能提交。
   例外：commit 沒有任何檔案變更（git commit --allow-empty 的存檔點）時，hook（check.py --commit）不跑檢查、直接通過；有變更照常完整檢查。
   手動檢查：python scripts/check.py（一般檢查，約 35 秒；git hook 跑的就是這個）
   完整檢查：python scripts/check.py --all（多跑標成 slow 的慢測試：真的 Windows 視窗、子程序，時間差不多）
   平行執行（2026-10-15 起）：check.py 用 pytest-xdist 平行跑（-n，最多 8 個；20 執行緒的筆電 1 個要 105 秒、8 個 28 秒），
      標成 @pytest.mark.依序 的測試（真的 Windows 視窗的前後順序等，不能和別的測試同時跑）平行的跑完後再單獨依序跑。
      直接打 python -m pytest 仍是依序跑（約 100 秒），適合只跑一兩個測試檔。自己加 -n 平行跑要先設 PYTHONUTF8=1
      （PowerShell：$env:PYTHONUTF8='1'），專案路徑有中文，沒設的話平行的子程序啟動失敗（INTERNALERROR EOFError）。
   什麼時候要跑完整檢查：改到視窗層級相關的程式（置頂、滑鼠提示、膠囊、面板的視窗樣式或前後順序，panel.py／capsule.py／overlay.py／提示置頂）、
   打包成 .exe 前、發版前。標慢測試的方法：在測試函式上加 @pytest.mark.slow（設定在 pyproject.toml）；慢測試不能刪、--all 要全過。

檢查更新：update_check.py。程式啟動後（app.py main()，測試不會觸發）在背景向 GitHub API（SquirrelRay/LiveSummary 的 releases/latest，逾時 5 秒）查最新發布版，
   逐段比整數版本號（1.0.10 比 1.0.9 新）；有新版跳出視窗（前往下載／稍後／略過這個版本，略過的版本記在介面設定.json 的 略過版本）。
   只通知，不自動下載安裝；不傳送個人資料。網路不通、404（專案或發布版還不存在）、逾時、格式不對一律安靜跳過，只在 logs\更新檢查紀錄.txt 記一行。
   設定框「關於」有開關「啟動時檢查更新」（config.json 的 check_update，預設開）。倉庫與贊助網址只寫在 version.py。
