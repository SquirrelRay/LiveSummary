直播重點摘要（階段 1）

第一次設定：
1. 安裝套件：pip install anthropic
2. 設定金鑰（只做一次，PowerShell）：
   setx ANTHROPIC_API_KEY "你的金鑰"
   設完後「關掉再重開」終端機才會生效。

使用：
   python summarize.py sample.txt --type game
   python summarize.py 文字稿.txt --type chat

結果會印在畫面上，並存成「原檔名_摘要.md」。

設定檔 config.json（用 live_topics.py 時）：
  功能開關和常用數字都寫在 config.json，用記事本打開改就好，改完存檔，下次執行就生效。
  config.json 是本機檔案，不進 git；git 裡只有範例 config.example.json（內容 = 出廠預設）。
  沒有 config.json 時（例如剛 clone）程式照常啟動、全部用出廠預設，不會自動建立；
  想用記事本改就把 config.example.json 複製成 config.json 再改，或直接在設定框按「儲存」（會建立 config.json）。
  預設值、欄位檢查、欄位說明、語言清單、讀寫 config.json 的程式都在 config.py（新增欄位只要改那裡，加上設定框）。
  命令列參數只是「這一次」臨時覆蓋，優先順序：命令列 > config.json > 程式內建預設。
  欄位：chat（聊天室）、minute_summary（分鐘摘要）、save_audio（存音訊）、fix_with_chat（聊天室參考詞修正）、
        check_minutes、min_topic_min、max_topic_min、model、whisper_model、language、minute_sentences（1 到 3）。
  看目前實際生效的設定與來源：  python live_topics.py --show-config
  臨時覆蓋範例：  --no-chat / --chat、--no-minute / --minute、--no-save-audio / --save-audio、--fix / --no-fix
  注意：API 金鑰不要寫進 config.json，只放在環境變數（預設 ANTHROPIC_API_KEY，可用 api_key_env 改名字）。
  金鑰無效時，程式會用一句中文停下來，不會繼續空跑。

外語直播（日文等）：
  config.json 的 language 可填 "zh"（預設，中文）、"ja"（日文）、"en"（英文）、"ko"（韓文）、"auto"（自動偵測）。
  命令列臨時覆蓋：  python live_topics.py --live 網址 --lang ja     或   --lang auto
  auto：用第一段（8～20 秒，依字幕速度）有人聲的音訊判斷語言（靜音或只有音樂的段會跳過、等下一段），判斷出來就鎖定，之後都用這個語言；失敗會印警告並退回中文。
  不管直播什麼語言，摘要一律是繁體中文；專有名詞第一次出現會附原文，看不懂的詞會標「不確定」。
  轉錄外語影片：  python transcribe.py 影片或網址 --lang ja
  文字稿模式跑外語稿：  python live_topics.py 日文稿.txt --lang ja
  --show-config 會顯示 language 目前的值與來源。

切換語言模型（live_topics.py；config.json 改這幾欄）：
  provider     ："anthropic"（預設，Claude）或 "openai_compatible"（OpenAI、DeepSeek、Ollama 等）
  base_url     ：服務網址，空白 = 該家預設
  api_key_env  ：金鑰放在哪個「環境變數名稱」（不是金鑰本身！）；留空 = 不需要金鑰（Ollama）
  model        ：模型名稱
  price_input / price_output：每百萬 token 的美元單價，只用來估算費用（單價未查證，請自行到官網確認）
  呼叫模型的程式都在 llm.py。summarize.py 單獨使用時仍固定用 Claude。
  用 openai_compatible 前要先裝套件：pip install openai
  金鑰無效、或連不上伺服器（例如 Ollama 沒開）時，程式會用一句中文說明並停止。
  拿不到 token 數的服務，結束時會顯示「無法計算」。

  範例（2026-10-10 查官方文件；模型名稱常會更新，用之前請再到官網確認）：
  OpenAI：（金鑰先 setx OPENAI_API_KEY "你的金鑰"）
    "provider": "openai_compatible", "base_url": "https://api.openai.com/v1",
    "api_key_env": "OPENAI_API_KEY", "model": "gpt-6-luna"
    （base_url 是從官方範例網址推得的；gpt-6-luna 是官方列的小型便宜款，大型款 gpt-6-astra）
  DeepSeek：（金鑰先 setx DEEPSEEK_API_KEY "你的金鑰"）
    "provider": "openai_compatible", "base_url": "https://api.deepseek.com",
    "api_key_env": "DEEPSEEK_API_KEY", "model": "deepseek-flash"
    （另有 deepseek-v4-pro）
  Ollama（本機，不用金鑰，先開 Ollama 並下載模型）：
    "provider": "openai_compatible", "base_url": "http://localhost:11434/v1",
    "api_key_env": "", "model": "gpt-oss:20b", "price_input": 0, "price_output": 0
    （model 換成你自己用 ollama pull 下載的模型名稱）
  換回 Claude：
    "provider": "anthropic", "base_url": "", "api_key_env": "ANTHROPIC_API_KEY", "model": "claude-haiku-5-5"

舊的摘要框／字幕框與精簡模式已移除（由啟動面板 → 浮動膠囊 → 可自由擺放的面板取代）：
  全域快捷鍵（Ctrl+Shift+S／A／D／X）、主控台的「字幕」「面板」「精簡」按鈕、Ctrl+Shift+M 都沒有了。
  config.json 裡舊的 overlay 區塊與 hotkey_compact 已停用：讀入時直接忽略、不跳警告，設定框儲存時也不會改寫或刪除它們。
  overlay_位置.json、介面設定.json 裡的「精簡」不再讀取，留著無妨。

設定框（啟動面板的齒輪、膠囊／系統匣選單的「設定」；主控台已沒有「設定」分頁）：
  可調字幕模式、聊天室、分鐘摘要、參考詞修正、延伸思考、聊天室翻譯與每分鐘上限、分鐘摘要句數、內容顯示方向、各分頁顯示上限、字幕速度、模型服務與模型名稱、存檔。
  按「儲存」才寫回 config.json，寫之前自動備份成 config.backup.json，先寫暫存檔再取代（寫到一半失敗原檔不會壞）；只改表單上的欄位，其他欄位原樣保留。
  膠囊選單的「顯示用量」也用同一套寫法。
  「還原預設值」會把表單變回出廠預設（config.py 的固定值，不受上一場影響；一樣要按「儲存」才寫入）。金鑰只顯示「已設定／未設定」。
  執行中改到的功能、模型等項目會標「下次開始生效」。

逐句翻譯（字幕模式 subtitle_mode："original" 原文、"translate" 一律翻譯、"auto" 中文原文其他語言翻譯）：
  語言選「自動偵測」時，偵測到外語後字幕會自動切成翻譯。
  翻譯呼叫已關閉延伸思考並限制輸出長度，費用約為原本的 1/6。
  批次由「字幕速度」段位決定（見下方）；舊的 translate_batch_seconds、translate_batch_lines 已停用，config.json 裡留著也不會警告、會被忽略。
  翻譯另外計費，主控台「翻譯」藥丸與結束訊息會分開顯示次數與費用。

逐句翻譯分頁、並排、網址紀錄（介面 app.py 才有）：
  逐句翻譯分頁：每則顯示時間、譯文（主）和較小較淡的原文。翻譯模式下，同時即時存成「原檔名_逐句翻譯.txt」
  （第一句寫入時才建立；同名舊檔已存在就改用加了時間的新檔名，不覆蓋）。翻譯失敗或逾時沒翻的句子存原文並標「【未翻譯】」。
  原文模式（例如中文直播）：分頁只顯示原文，頂端註明「目前為原文模式」，不另存檔。
  翻譯要「逐句翻譯」面板開著才會進行（沒開就不翻，省費用；其他面板不需要翻譯）。分頁最多顯示幾則：config.json 的 ui_max_translation（預設 500），超過顯示「較早的內容已存檔」與「打開檔案」。
  並排：分頁列右邊的「並排」選 1／2／3 欄，每欄各有一條分頁列，各自選要看的分頁；同一個分頁只會在一欄出現，
  在這一欄選到別欄正在看的分頁會兩欄互換。視窗窄於約 1100 自動剩 1 欄、窄於約 1600 最多 2 欄，變寬自動回到你選的欄數。
  欄數與每欄選的分頁記在 介面設定.json（本機檔案，不進 git）。
  網址紀錄：點直播網址欄會列出最近用過的 10 個網址（顯示頻道名稱），點一下填入；★ 可釘選（固定在最上方，不計入 10 個），✕ 刪除。
  只有成功開始擷取的網址才會記下，存在 網址紀錄.json（本機檔案，不進 git）。
  設定框的數字欄位、下拉選單：沒點選時滑鼠滾輪只捲動整個設定頁，不會誤改數值。

聊天室翻譯（介面才有；config.json 的 chat_translate，預設關；舊的 config.json 沒有這兩個欄位也當作預設、不跳警告）：
  外語直播時把聊天室留言翻成台灣慣用繁體中文。三個條件都成立才翻：設定開著、聊天室面板開著、直播語言是外語（自動偵測要等偵測到外語）。
  開關：設定框的「聊天室翻譯」（按儲存當場生效），或膠囊選單「聊天室翻譯：開／關」（當場生效，並寫回 config.json）。
  顯示：留言先不出現，等它那一批的譯文回來，原文（淡色）與譯文（「↳ 譯文」較亮）一起出現，不會先出原文再補譯文而閃動；
        大約晚 4～12 秒，最多 20 秒一定出現（API 很慢時以原文出現）。被跳過、被抽樣略過的留言照原本時間順序和前後留言一起出現。
        聊天室翻譯沒在翻（設定關、聊天室面板沒開、中文直播）時，留言照舊立刻出現。
        膠囊選單「面板 → 聊天室 設定 → 只看譯文」：有譯文的留言只顯示譯文。被跳過或沒翻到的留言只顯示原文。
  不翻的留言：草、www、888、單一字元重複、純數字、固定短語（はい、おつ…）、純表情代碼（Twitch 表情）、純符號；
        外語直播中全漢字的留言當作該外語（例如「全然大丈夫」會翻）。
  批次與上限：最多等 8 秒或累積 40 則送一次；每分鐘最多翻 chat_translate_max_per_min 則（預設 30），熱門台超過就平均抽樣，沒抽到的只顯示原文。
  不拖慢字幕：聊天室翻譯有自己的佇列與背景執行緒，和逐句翻譯完全分開；碰到 API 速率限制（429）就暫停 60 秒、不重送；
        排隊超過 20 秒還沒送的留言放棄翻譯。翻譯失敗一律只顯示原文。
        啟動里程碑紀錄會記下第一則聊天留言、第一批聊天翻譯送出（等了幾秒）與回來（API 花幾秒）、第一則聊天顯示，方便查延遲。
  迷因：提示詞裡有固定對照（草→笑死、888→拍手、乙／おつ→辛苦了、てぇてぇ→好貼…），對照表在 chat_translate.py 的 迷因對照，之後要加改那裡；
        不認得的梗保留原文，不硬翻、不解釋。
  費用另外計：狀態列「聊天翻譯」藥丸（開著或用過才出現）、膠囊滑鼠提示、結束訊息都會分開顯示次數與費用。
        啟動面板總費用、ⓘ 比較表、設定框費用表多一項「聊天室翻譯」（以中等聊天量估算，約 $0.21／小時；熱門台有上限封頂約 $0.30／小時；都是估算）。

按「停止」後會顯示「正在產生最後一個話題的摘要，約需 10 秒…」，完成後膠囊旁出現幾秒後自動消失的小提示（「已結束」，有存檔時「已結束，已存檔」），不再跳彈窗。

字幕速度（config.json 的 subtitle_speed，預設 "balanced"；沒有這個欄位也當作平衡、不跳警告）：
  在「字幕出得快」與「轉錄比較準、翻譯比較省」之間選一個段位：
    "fast"     速度：分段 8 秒，翻譯批次最多等 1 秒或累積 8 句
    "balanced" 平衡：分段 12 秒，翻譯批次最多等 1 秒或累積 8 句
    "accurate" 準度：分段 20 秒，翻譯批次最多等 8 秒或累積 8 句
  分段越短第一句越早出現，但句子比較常被切斷、偶爾有辨識錯誤；分段越長越穩，翻譯呼叫次數也越少。
  各段位的整體字幕延遲與準確度：速度＝翻譯字幕約慢 8 秒、偶爾斷句錯字；平衡＝約慢 11 秒、準確度佳（建議）；準度＝約慢 18 秒、最準最省錢。
  啟動面板第二行與設定框的「每小時費用」表，依 config.json 目前的單價，估算每小時總費用與各功能（字幕翻譯、換話題判斷、分鐘摘要、話題摘要）各花多少；
  沒開的功能（逐句翻譯面板沒開、中文直播、分鐘摘要關閉）顯示「未開啟 $0」且不計入。金額是估算，實際以 API 帳單為準。
  啟動面板語言旁的「速度／平衡／準度」只影響這一場，不寫回 config.json；下次打開啟動面板會回到設定框的預設。
  一律下次開始生效：啟動中與直播中不能切換（分段長度在一場直播中固定，中途改會讓時間戳錯位）。
  每次開始時，logs/啟動里程碑 檔的開頭會記下段位、分段秒數與翻譯批次。

啟動面板（python app.py 開程式時出現，主控台不會自動出現）：
  網址欄（點一下有網址紀錄）、語言（預設「自動偵測」）、字幕速度（速度／平衡／準度）、開始、右上角齒輪（設定）、✕（收起）。
  按「開始」＝主控台的「開始」；成功開始擷取後啟動面板收起，並套用上次使用的版面（沒有就用預設版面）讓面板出現。
  按下開始後面板顯示「啟動中…（目前階段）」與跑動的進度條，開始鈕停用；啟動中也可按「結束」直接關閉程式（不需確認）。
  網址錯誤、頻道沒開播等錯誤直接顯示在啟動面板裡。收起後可從膠囊／系統匣選單「開始…」打開（直播中沒有這項）。
  膠囊／系統匣選單另有「設定」（和齒輪同一個設定視窗）、「顯示主控台」。關閉主控台只是收起，要結束程式請用「結束程式」。

存檔（設定的「存檔」區，config.json 的 save_summary、save_transcript、save_chat、save_translation、save_audio，預設全關）：
  打開的項目才寫檔（存在專案資料夾，「打開存檔資料夾」可直接打開）；關掉的內容只顯示在畫面上，
  分頁與面板超過顯示上限時顯示「較早的內容已移除」（沒有「打開檔案」）。直播稿、聊天室、音訊只在直播網址模式有作用。

版本存檔（Git，只存在這台電腦，不會上傳）：
  存一個新的存檔點：  git add -A && git commit -m "這次改了什麼"
  回到上一版（放棄還沒存檔的修改）：  git restore .
  回到上一個存檔點的樣子（保留歷史）：  git revert HEAD
  看有哪些存檔點：  git log --oneline

直播時間（直播網址模式）：
  直播稿、逐句翻譯、聊天室、分鐘摘要、話題摘要的時間都是「直播實際進行時間」（例如 1:23:45，和 Twitch 重播的時間軸一致），不是軟體啟動後多久。
  開播時間：按開始時和開播檢查同時查（Twitch 網頁公開資料為主，頻道網頁備援；不需要金鑰、不用第三方服務；每次 3 秒逾時，按「結束」可中斷）。
  換算：句子 = 第一段音訊的直播時間 + 音訊秒數；聊天室留言 = 收到時刻 − 開播時間 − 串流延遲（約 11 秒，和直播稿對齊）。誤差約 ±3～5 秒。
  廣告被濾掉或斷線造成音訊少一段時，會自動把之後的時間往前補（只往前、不倒退），並顯示一行提示。
  時間格式：未滿 1 小時 mm:ss，滿 1 小時 h:mm:ss（timefmt.py 是唯一來源）。
  抓不到開播時間：時間改從開始擷取起算並在前面加「+」（例如 [+12:34]，存檔與模型也一樣），狀態列時間藥丸變黃並寫「抓不到開播時間」，
                  開始時膠囊旁提示一次，分鐘摘要與話題摘要卡片自動顯示「幾分鐘前」。
  時間顯示（config.json 的 time_display："stream" 直播時間（預設）、"ago" 幾分鐘前；舊的 config.json 沒有這個欄位也當作預設、不跳警告）：
    只影響分鐘摘要與話題摘要卡片；直播稿、逐句翻譯、聊天室一律顯示直播時間。設定框（按儲存）或膠囊選單「時間顯示」切換，當場生效。
    「幾分鐘前」每分鐘更新一次（分鐘數變了而且看得到才重畫）。
  直播主、標題、分類：只顯示在膠囊滑鼠提示與各存檔開頭（「# 」開頭的幾行；文字稿模式重讀時會略過），不放狀態列、不送給模型。
  待辦：直播主斷線後重新開台時，開播時間會變，目前不會重新查（下一場重新開始即可）。

啟動時間里程碑紀錄：每次按「開始」，會在 logs/啟動里程碑_日期_時間.txt 記下各階段（模型載入、第一段音訊、第一段轉錄、第一句翻譯、第一句顯示）從按下開始起算的秒數，不含金鑰。
面板（分鐘摘要、話題摘要、逐句翻譯）還沒有內容時，會依階段顯示「載入模型中…／聆聽中，等待第一段…／轉錄與翻譯中…」，第一句出現後消失。

狀態列的「語言」藥丸：一直顯示目前語言（例如「語言：日文（自動偵測）」「語言：日文（手動）」，自動偵測中顯示「偵測中…」）。
語言設為自動時，旁邊有「重新偵測」鈕（膠囊選單也有，固定在「開始…／停止」下方）：不中斷直播，用下一段有人聲的音訊重新判斷。信心低於 0.4 時，第一次會退回中文並明確標示「偵測不確定」；重新偵測低信心則維持原語言。
主控台收著時也看得到語言警告：偵測不確定或失敗時，膠囊上多一段黃色「⚠ 語言」（燈色不變），膠囊旁跳出約 8 秒的提示；
膠囊與系統匣的滑鼠提示也會顯示目前語言。重新偵測成功或按停止後，「⚠ 語言」就消失。
錯誤提示：直播中途的錯誤（例如金鑰失效）、config.json 的設定警告，除了主控台的提示條，也會在膠囊旁用紅框中文提示約 12 秒。
啟動中的錯誤（網址錯誤、沒開播）照舊顯示在啟動面板裡。

話題切分的做法（live_topics.py；2026-10 調整，之後用實際直播驗證，不再用 VOD 調整切分邏輯）：
  目標：「一件事一題」是主要的切法，15 分鐘上限（max_topic_min）只當保險；最短 3 分鐘（min_topic_min）。
  1. 錨點：每個話題在開始時定下「那一件事」（10～20 字，模型的 topic 欄位），之後不改寫；每輪（check_minutes，預設 1 分鐘）判斷新文字是不是還在聊這件事。
     原因：以前拿每輪改寫的簡述比對，簡述會吸收新內容，話題漂移後永遠判「延續」，模型很少回 new_topic。
     簡述（topic_brief）仍每輪更新，只給介面顯示，不參與判斷。提示詞不含話題已進行多久、不含話題長度或標題。
  2. 換話題規則（換話題規則，live_topics.py）：一個話題＝一件事；算 new_topic、算 same 的條件都寫在裡面；沒有跟任何直播內容有關的例子。
  3. 被最短分鐘數擋掉：模型判 new_topic 但話題還沒滿 min_topic_min（或切點對不上稿裡任何一行）時，不切話題，但錨點換成新的那件事，
     之後的輪次跟新的事比對（否則新的事會一直被當成舊錨點的延續）；話題開始時間不動（那些行確實在這一題裡）。
  4. 錨點只能是一件事：提示詞要求不可用「與」「、」「及」「並」串接；引擎再保一道（單一主題()）：遇到 與／与／及／並／并／、／／／斜線／逗號 等，只留第一件
     （第一件短於 2 字就原樣保留；「和」「跟」不切）。
  5. 打招呼、感謝訂閱或贈禮、念聊天室留言不能當錨點，也不能成為被擋時換上的新錨點：提示詞禁止，引擎用關鍵字再擋一次（是雜訊主題()，關鍵字在 雜訊主題）；
     這類 topic 當作沒給，保留原本的錨點（話題剛開始還沒有錨點時，等下一輪有正常的事再定下）。
  6. 話題摘要的標題：只寫這一題最主要的那一件事，不用「、」「與」「並」「及」串接，次要內容放在【摘要】內文（話題格式 的【話題標題】那一行）。
  已知限制：
  - 模型判斷「一件事」的粒度不穩定：有時把同一件事判成換題（買手機→買新手機）、有時把幾件事放在同一題；同一場直播的結果也會因模型回答不同而略有出入。
  - 短於 3 分鐘的話題會被併入前一題（被擋掉的那件事沒辦法獨立成題）；3 分鐘下限由 min_topic_min 決定，沒有放進提示詞。
  - 被擋時錨點若換成很細的小事，之後可能長時間判 same，直到撞上 15 分鐘上限。
  - 標題是模型寫的，規則只在提示詞裡，沒有引擎檢查，仍可能出現串接。
  - 雜訊主題的關鍵字比對很簡單，極少數正常主題剛好含「訂閱」「感謝」之類的字時，會被當成沒有錨點。
  重跑與對照：開發用 VOD 轉錄與重播的做法見下一段；每次調整後的數字（題數、撞上限次數、費用）在對話紀錄裡，沒有另外存檔。

直播主專有名詞詞庫（glossary.py；一律開著，沒有 config.json 欄位）：
  用途：讓同一個直播主的人名、作品名、遊戲名、地名、梗名在摘要裡寫法前後一致（這一場之後的摘要、下一場都沿用）。不上網、不增加模型呼叫次數。
  放哪：專案資料夾的 詞庫/直播主.txt（本機檔案，不進 git）。檔案不存在就當作空的，第一次自動加入名詞時才建立。
  哪個直播主：直播網址模式用頻道名稱（網址最後一段，例如 https://www.twitch.tv/abc → 詞庫/abc.txt）；
            文字稿模式用 --streamer 指定，例如  python live_topics.py 稿.txt --lang ja --streamer abc
            沒給 --streamer（或從介面用文字稿重播）就不讀、不寫詞庫，其他照舊。
  格式：UTF-8 純文字，每行一個名詞「中文寫法｜原文｜來源」，例如
            艾連｜エレン｜手動
            米卡莎｜ミカサ｜自動
        來源：手動、自動（之後的「上網查資料」會寫「上網」）。中文直播的名字可以只寫「中文寫法」；沒寫來源的行當作手動。
        「|」半形全形都可以；「#」開頭的行是說明。格式不對的行（欄位太多、來源不認得、沒有寫法）會略過不用，但檔案裡保留原樣。
  手動加／刪：用記事本打開，照格式加一行（例如先把成員名、作品名填進去）；不要的整行刪掉；存檔用 UTF-8。下次開始時生效
        （直播中改的，下一次自動加入名詞時也會讀到）。手動的行程式永遠不會改動或刪除。
  運作：開始時讀入並印「已載入詞庫：直播主，N 個名詞」；每一輪換話題判斷（含分鐘摘要）與每次話題摘要的提示詞附上詞庫，
        最多 30 個（手動的優先，其次是稿裡出現的、這一場最近用到的、較晚加入的）；詞庫是空的時提示詞不出現這一段。
        要求模型：稿裡出現詞庫中的名字時沿用詞庫寫法；稿裡沒提到的不可因為詞庫有就寫進摘要；詞庫沒有的照原本規則。
        話題摘要那一次呼叫順便在最後一行列出【名詞】（只列有把握的，「不確定」的不列）；這一行不會顯示、不會存進話題摘要檔。
        自動加入的條件：原文（沒有原文就看中文寫法）真的出現在這一題的語音稿裡（模型常把詞庫整串抄進清單，稿裡沒提到的不收）；
        中文寫法裡不能有假名或日文字形（例如 弾、鉄）；模型寫反成「原文（中文）」時自動對調；詞庫裡還沒有這個原文。
        符合的接在檔案最後（來源「自動」），並印「詞庫新增：…」。每次寫檔先寫暫存檔再取代，寫到一半失敗原檔不會壞。
        詞庫檔讀不懂（例如不是 UTF-8）時印一行提示，這一場不使用也不寫入，原檔不動。
  已知限制：
  - 詞庫只保證寫法一致、不保證正確：第一次寫錯的名字（例如翻譯不準），之後會一直沿用同一個錯的寫法。
  - 轉錄（Whisper）就聽錯的名字救不了：詞庫只能比對稿裡已經寫出來的原文。
  - 自動加入的錯字會一直沿用：看到錯的請直接刪掉那一行，或改成正確寫法並把來源改成「手動」。
  - 模型只願意寫假名、沒給中文寫法的名字（例如 VTuber 的暱稱）不會自動加入，寫法仍可能前後不一；這類名字請手動加（例如「曼太郎｜マン太郎｜手動」）。
  - 模型偶爾把一般詞彙（食物、日用品）也列成名詞，會被收進詞庫；看到就刪。
  - 「最近用到」只記在這一場裡；跨場時自動加入的名詞以檔案順序（較晚加入的優先）決定，超過 30 個時較舊的不會放進提示詞。

開發者：用 Twitch VOD 測試話題切換與 h:mm:ss 時間格式（開發工具，不是產品功能，不在介面裡）：
   不用看完整場直播：把 VOD 的指定時段轉成直播稿，再用「文字稿重播模式」快轉跑摘要。
   1. 轉成直播稿（只下載該時段的音訊、本機 Whisper 轉錄，不花 API 費用；需要已裝 streamlink、ffmpeg，沒有顯示卡會很慢）：
        python scripts/vod_to_transcript.py https://www.twitch.tv/videos/2898838036 --start 0:06:25 --end 1:30:00 --lang ja
      --start 沒給就從 0 開始，--end 沒給就到 VOD 結尾；--lang 可填 zh、ja、en、ko、auto（自動偵測，用 5 段音訊投票；VOD 開頭是音樂或等待畫面時可能判錯，不確定就直接指定）。
      音訊與直播稿放在 測試素材/（已被 .gitignore 忽略），檔名像 vod2898838036_0h06m25s-1h30m00s_直播稿.txt。
      時間戳是 VOD 內的原始時間（和 Twitch 播放器對得上），超過 1 小時是 h:mm:ss。
      streamlink 只能從 VOD 的分段邊界開始（約 10 秒一段），所以實際起點可能比 --start 晚幾秒；實際起點寫在直播稿開頭「# 」開頭的說明行（重播時會略過）。
      只處理音訊與直播稿，不抓 VOD 聊天室。
   2. 用重播模式跑摘要（會呼叫摘要模型，花 API 費用；設定照 config.json）：
        python live_topics.py 測試素材/vod2898838036_0h06m25s-1h30m00s_直播稿.txt --lang ja --speed 0
      --speed 0 = 不等待、瞬間讀完（最快，實際速度只受 API 回應時間限制）；--speed 60 = 60 倍速；--speed 1 = 真實速度。
      快轉只影響讀稿的等待時間，不影響換話題判斷：判斷是依稿裡的時間（--check 幾分鐘一次）和文字量決定，不看現實時鐘，所以 --speed 0 與 --speed 60 的結果相同。
      文字稿模式不能自動偵測語言，請用 --lang 指定（config.json 的 language 是 auto 時，不指定會照外語說明處理）。
      不從 0:00 開始的直播稿可以直接跑：第一行的時間就是第一輪檢查的起點，話題與摘要的時間都用稿裡的原始時間。
      結果檔（話題摘要、分鐘摘要）會存在直播稿旁邊的 測試素材/（config.json 的 save_summary 開著才存）；也可以用介面的「文字稿」來源重播同一份直播稿。
   3. 摘要費用估算（用目前單價 Haiku 輸入 $1／輸出 $5、延伸思考關、沒有聊天室、分鐘摘要開，cost_estimate.py 的估算，實際以 API 帳單為準）：
        每小時直播稿約 US$0.24（換話題判斷約 $0.13、分鐘摘要約 $0.09、話題摘要約 $0.03）；1.5 小時約 US$0.37。
      延伸思考開著時輸出約 3.7 倍，費用大約再多一倍以上。
